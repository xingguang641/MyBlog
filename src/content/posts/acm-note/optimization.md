# 枚举技巧与优化

在算法问题中，枚举既是最自然的建模方式，也是理解问题结构的重要工具。通过枚举候选状态、方案或结构组合，可以确保解空间被完整覆盖，因此枚举常常作为解题的第一步。然而，枚举并不仅仅是一种 “暴力尝试” ，它本身也蕴含着丰富的组织方式与技巧。不同的枚举策略，对状态空间的展开顺序、覆盖效率以及后续优化空间，都有着决定性的影响。

进一步地，当问题规模增大时，直接枚举往往会遭遇复杂度瓶颈。这并不意味着枚举思想本身失效，而是说明 **枚举方式尚未与问题结构充分匹配** 。因此，有必要从两个层面理解枚举：一是如何正确、系统地展开枚举空间；二是在此基础上，如何削减冗余枚举，使算法在保持正确性的同时具备可行的时间复杂度。后续内容正是围绕这两个层次展开。

## 常见枚举技巧

枚举技巧关注的是 **如何有序、完整地遍历候选空间** 。在许多问题中，状态本身并非天然适合直接多重循环展开，而需要通过特定的表示方式或生成规则，才能高效地进行遍历。

典型的例子包括二进制枚举，用于表示选取与否的子集状态；排列枚举，通过字典序或 `next_permutation` 的方式遍历所有排列；以及基于递归或 DFS 的结构化枚举，用来生成组合、划分或树形结构。这些方法的共同特点在于：**它们并不改变枚举的本质，但通过状态表示与生成顺序的设计，使枚举过程更加规整、可控** 。

合理的枚举技巧不仅能够减少实现复杂度，还能为后续的剪枝、优化或状态压缩创造条件。在许多高效算法中，优化并非直接作用于结果计算，而是首先体现在枚举阶段的结构设计上。

## 常见枚举优化

当枚举空间本身不可避免时，优化的目标便转向 **减少实际被执行的枚举次数** 。枚举优化并不是否定枚举，而是通过分析问题结构，识别哪些枚举是冗余的、等价的或低贡献的，从而对枚举过程进行压缩。

常见的优化思路包括：合并等价状态以避免重复遍历，利用问题的单调性或对称性缩小枚举范围，通过数学关系将显式枚举转化为公式计算，或借助数据结构维护中间结果，避免在不同枚举分支中反复计算相同信息。这些方法往往保留了 “枚举” 的外在形式，但其复杂度已经发生了本质变化。

从更高层次看，枚举优化的核心在于：**并非所有枚举状态都同等重要** 。一旦能够刻画哪些状态真正影响最终答案，枚举便可以从 “全覆盖式遍历” 转变为 “结构引导式搜索” ，从而成为一种高效而可靠的算法工具。

# 基础枚举技巧论

在算法实现中，**枚举是极为常见且基础的一类操作** 。无论是遍历状态空间、构造候选方案，还是对中间结果进行验证，枚举都承担着将抽象问题转化为具体计算过程的作用。由于其形式直接、逻辑清晰，枚举往往是解题过程中最早被采用的手段之一，也常常作为更复杂算法的出发点或验证手段。**在许多问题中，即便最终解法并非暴力枚举，枚举仍然在思路推导与结构分析阶段发挥着重要作用** 。

然而，枚举的实现方式并非只有简单的多重循环这一种选择。通过合理的 **状态表示、遍历顺序以及构造方式** ，可以使枚举过程更贴合问题的结构特征，从而在表达上更加简洁、逻辑上更加清晰。这类技巧主要关注的是 **枚举过程的组织方式本身** ，虽然不一定改变问题的规模或复杂度，但往往能够降低实现难度，并为后续的推导与改写提供更稳定的基础。

## 子集的枚举技巧

最直观的子集枚举方式，是按照元素顺序，对每一个元素依次做 “选或不选” 的决策。这种思路与人类思考子集的方式完全一致，其自然实现形式就是深度优先搜索（DFS）。设集合大小为 $n$ ，我们从第 $0$ 个元素开始处理，在递归的第 $i$ 层决定元素 $a_i$ 是否被加入当前子集。当所有元素都被处理完时，就得到了一个完整子集。整个搜索树是一棵深度为 $n$ 的二叉树，总共包含 $2^n$ 个叶子节点。

```cpp
vector<int> a;    // 原集合
vector<int> cur;  // 当前子集
int n;

void dfs(int i) {
    if (i == n) {
        // 此时 cur 就是一个子集
        // 在这里处理 cur
        return;
    }

    // 不选 a[i]
    dfs(i + 1);

    // 选 a[i]
    cur.push_back(a[i]);
    dfs(i + 1);
    cur.pop_back();
}
```

这种 DFS 枚举方式的特点在于：结构非常清晰，递归层数与元素个数一一对应，并且在枚举过程中可以自然地加入剪枝条件或提前返回逻辑。因此，当题目需要在枚举过程中动态维护信息、或根据部分选择判断可行性时，这种写法往往最容易控制和修改。

另一种同样基础、但更偏向工程实现的方式，是 **使用二进制掩码枚举子集** 。其核心思想是用一个整数的二进制表示来刻画子集状态：第 $i$ 位为 `1` 表示选择第 $i$ 个元素，为 `0` 表示不选择。这样，从 `0` 到 `(1<<n)-1` 的所有整数，恰好一一对应集合的所有子集。对每一个状态，只需检查每一位是否为 `1`，即可还原出当前子集包含哪些元素。

```cpp
vector<int> a;
int n;

for (int mask = 0; mask < (1 << n); mask++) {
    vector<int> subset;
    for (int i = 0; i < n; i++) {
        if (mask & (1 << i)) {
            subset.push_back(a[i]);
        }
    }
    // subset 即为当前子集
}
```

这种枚举方式的优势在于：状态表示极为紧凑，判断元素是否被选只需一次位运算，并且非常适合与状态压缩动态规划等算法结合使用。从本质上看，它与 DFS 枚举并没有任何区别，只是将 “选或不选” 的递归决策过程，直接编码进了二进制表示中。

在位掩码表示的基础上，还存在一种非常重要且高频使用的技巧：**在给定一个集合 $S$ 的前提下，枚举它的所有子集** 。这时不再从 `0` 枚举到 `(1<<n)-1` ，而是只关心那些满足 “是 $S$ 的子集” 的状态。经典写法如下：

```cpp
for (int j = S; j; j = (j - 1) & S) {
    // j 是 S 的一个非空子集
}
```

该循环会 **不重不漏** 地枚举出 $S$ 的所有非空子集，且每个子集只访问一次。若需要包含空集，只需在循环结束后额外处理 `j = 0` 即可。

其原理在于：对当前子集 `j` 执行 `j - 1` 操作时，会将 `j` 的最低位 `1` 变为 `0`，并将其右侧的所有位变为 `1`。再与 `S` 进行按位与运算，就会自动清除那些不属于 `S` 的位置，从而得到一个 **严格小于 `j` 且仍是 `S` 子集** 的新状态。不断重复这一过程，便能按照递减顺序枚举出所有子集，直到 `j` 变为 `0` 为止。

这种写法在状态压缩动态规划中尤为常见，例如子集 DP 或需要遍历 “某个状态的所有子状态” 的场景。相比于枚举所有掩码再判断是否为子集，这种方式在表达和常数上都更加直接，也更贴合问题的语义结构。

## 排列的枚举技巧

在排列问题中，枚举的核心不再是 “选或不选” ，而是 **在不重复使用元素的前提下，确定每一个位置放什么** 。因此，最自然的建模方式是：把排列看成一个长度为 $n$ 的序列，枚举第 $0$ 位、第 $1$ 位直到第 $n-1$ 位依次放入的元素。这种视角下，排列枚举几乎可以直接套用 DFS 的框架。

最基础的做法是 **DFS 按位置填数** 。递归深度表示当前已经确定了多少个位置，在第 `pos` 层，从所有 “尚未使用过” 的元素中任选一个放到当前位置即可。为了保证每个元素只使用一次，通常会维护一个 `used` 数组，用来标记哪些元素已经被选过。递归到深度为 $n$ 时，当前序列就是一个完整排列。

```cpp
vector<int> a;      // 原始元素
vector<int> perm;   // 当前构造中的排列
vector<bool> used;
int n;

void dfs(int pos) {
    if (pos == n) {
        // perm 是一个完整排列
        return;
    }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = true;
        perm.push_back(a[i]);
        dfs(pos + 1);
        perm.pop_back();
        used[i] = false;
    }
}
```

这种写法的特点非常直接：每一层负责一个位置，每一次递归选择一个新元素加入排列。它的优势在于结构清晰、可控性强，非常适合在枚举过程中顺便维护额外信息或做剪枝；代价是需要显式维护使用状态，代码略显冗长。

如果换一个角度看排列，其实也可以认为：排列就是对数组进行一系列交换的结果。基于这种理解，可以得到 **原地交换枚举排列** 的写法。思路是：在递归的第 `pos` 层，决定 “哪个元素最终放在位置 `pos`” ，于是从区间 `[pos, n)` 中任选一个元素，与 `a[pos]` 交换，然后递归处理下一位。回溯时再交换回来，保证数组状态不被破坏。

```cpp
vector<int> a;
int n;

void dfs(int pos) {
    if (pos == n) {
        // 当前 a 即为一个排列
        return;
    }
    for (int i = pos; i < n; i++) {
        swap(a[pos], a[i]);
        dfs(pos + 1);
        swap(a[pos], a[i]);
    }
}
```

这种方法不需要额外的 `used` 数组，所有状态都体现在数组本身中。从本质上看，它和前一种 DFS 是等价的：前者是 “选一个没用过的元素放到当前位置” ，而这里是 “把某个候选元素交换到当前位置” 。在理解排列结构时，这种写法往往更有 “位置视角” 的直观性。

除了基于 DFS 的构造型枚举，还有一类非常常用的方式是 **直接按字典序枚举排列** 。这种方法并不关心排列是如何构造出来的，而是把 “排列本身” 当作一个状态，通过确定的规则在状态之间跳转。只要从字典序最小的排列开始，不断生成下一个排列，就可以在不重复、不遗漏的情况下遍历全部结果。

在 C++ 中，这一过程由 `next_permutation` 封装完成。只要先对数组排序，然后反复调用该函数即可。

```cpp
sort(a.begin(), a.end());
do {
    // 当前 a 是一个排列
} while (next_permutation(a.begin(), a.end()));
```

理解 `next_permutation` 的核心在于：该算法并非任意构造一个新的排列，而是 **在全体排列的字典序序列中，严格生成当前排列的直接后继** 。为实现这一目标，算法对排列结构进行了精确分析，并通过一组确定性的操作，在保证字典序连续性的同时完成状态转移。其具体过程可以分解为以下三个步骤。

* **从右向左确定首个上升点**
  从序列末尾向左扫描，找到第一个满足 $a[i] < a[i+1]$ 的位置 `i` 。该位置的存在表明：区间 `[i+1, n)` 已经处于在固定前缀 `a[0..i]` 条件下的最大排列状态，若要获得字典序更大的排列，唯一可能的修改位置只能位于 `i` 及其左侧。若不存在这样的 `i`，则说明整个序列为非递增序列，即已达到字典序的最大排列，不存在下一个排列。

* **在后缀中选择最小的可替换元素交换**
  在区间 `[i+1, n)` 中，从右向左查找第一个满足$a[j] > a[i]$ 的位置 `j` ，并交换 `a[i]` 与 `a[j]` 。这一操作的作用在于：在第 `i` 位对排列进行 **最小幅度的增大** ，从而保证新排列严格大于原排列，同时又尽可能接近原排列的字典序位置。

* **将后缀重排为字典序最小形式**
  交换完成后，区间 `[i+1, n)` 仍保持非递增状态。为了使整体排列在所有可能的后继中达到字典序最小，只需将该区间反转，使其变为递增序列。此操作确保后缀部分在当前前缀固定的条件下取到最小可能值。

正是由于上述三步分别在 **修改位置的选择、增量大小的控制以及后缀排列的最小化** 三个层面进行了严格约束，`next_permutation` 才能够在不依赖递归或额外状态记录的前提下，按照字典序顺序完整、无重复地遍历所有排列。

# 贡献法优化枚举

在算法设计中，许多问题表面上需要对大量对象或情况进行枚举，但直接枚举往往会带来难以接受的时间复杂度。尤其是在涉及区间、子结构或多次操作的问题中，若缺乏有效的整体视角，算法往往会陷入重复计算，效率低下。如何在保证结果正确的前提下减少不必要的枚举，是算法优化中的一个重要课题。

贡献法正是在这一背景下形成的一类重要思想。其基本出发点是重新审视问题中 “答案是如何被构成的” ，通过分析单个元素、操作或结构对最终结果所产生的影响，将复杂的整体计算拆解为若干可独立统计的局部贡献。借助这种思路，许多原本需要高复杂度枚举的问题，都可以被转化为更高效、结构更清晰的算法。

下面将从两种常见的形式出发，分别介绍局部变化贡献法和对象交换贡献法，说明它们的适用场景、核心思想以及典型应用方式。

## 局部变化贡献法

局部变化贡献法适用于这样一类问题：**整体答案是由许多局部成分累加而成，但每次操作只会影响其中极小的一部分** 。在这类问题中，虽然最终结果是一个全局统计量，但其变化往往来源于某一次操作所引发的 **局部状态改变** ，而非整体结构的重构。因此，答案的更新可以通过对 “变化部分” 的贡献进行修正来完成。

其核心思想在于分析 **一次局部修改相对于原状态所引入的差分贡献** 。与其在每次操作后重新计算整个答案，不如直接刻画 “这次修改到底改变了什么” 。只要能够精确描述这一变化对最终结果的影响范围，便可以在不触及其余不变部分的前提下完成更新。

以数组 `a[1..n]` 为例，假设需要支持多次单点修改，并频繁查询数组元素之和。若每次修改后都重新遍历数组计算总和，则单次操作的时间复杂度为 $O(n)$ ，在操作次数较多时显然不可接受。然而，注意到一次单点修改只会影响数组中 **一个位置的取值** ，其余元素对答案的贡献保持不变。

基于这一观察，我们只需维护一个变量 `sum` ，表示当前数组的元素之和。当位置 `i` 的元素由原值 `a[i]` 修改为新值 `x` 时，对总和的影响完全由这一局部变化决定：原本的贡献是 `a[i]`，修改后的贡献是 `x`，因此只需将 `sum` 增加 `(x - a[i])` 即可完成更新。查询操作则直接返回当前的 `sum`，无需任何额外计算。

通过这种方式，每次操作都只处理 **发生变化的局部信息** ，而不再重复计算未受影响的部分，从而将单次修改和查询的时间复杂度降为常数级。更重要的是，这种方法体现了一种典型的思维转变：**不从 “答案是什么” 出发重新计算，而是从 “哪里发生了变化” 出发修正答案** 。正是这种对局部变化贡献的精确刻画，使得算法在保持正确性的同时，获得了显著的效率提升。

## 对象交换贡献法

对象交换贡献法适用于答案由多个元素或子结构组合而成的情况，其核心思路在于 **倒过来思考问题**：不去枚举所有可能的整体情况，而是分析每个元素、每条边或者每个数字在最终答案中的 **具体贡献** 。通过将关注点从 “整体枚举” 转移到 “局部贡献” ，可以从根本上降低问题的计算复杂度。

以一个经典问题为例，假设我们要求一个数组中所有子数组的最小值之和。若直接枚举每个子数组并求最小值，时间复杂度至少是平方级的，在数据规模较大时难以接受。这种做法的低效本质在于 **重复计算了大量相同的信息** 。

如果换个思路进行观察，可以发现每个元素 `a[i]` 都会在若干个子数组中充当最小值。因此，只需统计每个元素成为子数组最小值的数量，再将元素值与该数量相乘并累加，便可直接得到最终答案。通过这种 **逐元素统计贡献** 的方法，不仅避免了重复枚举，还能将问题的复杂度大幅降低。

类似的思想在其他问题中同样适用。例如，在树上求所有路径权值之和时，可以从 **边的角度** 出发，统计每条边出现在多少条路径中，并将出现次数与边权相乘后累加；在计算所有点对的曼哈顿距离时，可以单独考虑每个点在横纵坐标上的贡献，通过排序和前缀和高效完成计算；在数论问题中，如求 1 到 n 中所有数的因子个数之和，也可以将每个数作为因子的出现次数视为其贡献，从而避免逐个枚举因子。

总的来说，贡献法的精髓在于 **从元素角度倒推答案** ，而不是从答案出发枚举所有可能。无论是整体规划贡献法还是对象交换贡献法，其核心都是明确每个元素或操作对最终结果的影响，并将这些影响量化后累加。这种方法不仅能够显著降低时间复杂度，还能让问题结构更加清晰直观，是解决复杂枚举类问题时 **极其重要的一种算法思想** 。

## 最小值之和查询

### Problem Statement

给定两个长度为 $N$ 的整数序列

$$
A = (A_1, A_2, \ldots, A_N) \quad B = (B_1, B_2, \ldots, B_N)
$$

以及一个整数 $Q$ 表示查询数量。每个查询会描述如下操作：

* 输入一个字符 $c_i$ 和两个整数 $X_i, V_i$：

  * 若 $c_i =$ `"A"` ，则将 $A_{X_i}$ 修改为 $V_i$
  * 若 $c_i =$ `"B"` ，则将 $B_{X_i}$ 修改为 $V_i$

在执行完该修改之后，计算并输出：

$$
\sum_{k=1}^N \min(A_k, B_k)
$$

即序列 $A$ 与序列 $B$ 的对应元素最小值之和。

### Constraints

* $1 \leq N, Q \leq 2 \times 10^5$
* $1 \leq A_i, B_i \leq 10^9$
* $c_i$ 只能是字符 `"A"` 或 `"B"`
* $1 \leq X_i \leq N$
* $1 \leq V_i \leq 10^9$
* 所有输入均为整数

### Input

输入包含多行数据，格式如下：

- 第一行包含两个整数 $N$ 和 $Q$ 。
- 第二行包含 $N$ 个整数，表示序列 $A$ 。
- 第三行包含 $N$ 个整数，表示序列 $B$ 。
- 接下来的 $Q$ 行中，每行表示一次查询，包括一个字符与两个整数。

> $N \quad Q$
>
> $A_1 \quad A_2 \quad \ldots A_N$
>
> $B_1 \quad B_2 \quad \ldots B_N$
>
> $c_1 \quad X_1 \quad V_1$
>
> $c_2 \quad X_2 \quad V_2$
>
> $\ldots$
>
> $c_Q \quad X_Q \quad V_Q$

### Output

输出 $Q$ 行，每行对应一个查询的结果，即执行修改并计算最小值之和后的输出。

# 随机化优化枚举

在某些问题中，如果在解题过程中不额外利用任何结构性信息，仅依据问题的原始描述进行判断，那么对所有候选情况进行枚举在理论上就是不可避免的。在这种情形下，枚举并非算法设计不当的结果，而是由问题本身所需的信息量决定的；若不逐一考察这些候选对象，就无法保证结论的正确性。

正因如此，这类问题往往会通过附加某些 **特殊条件** ，来改变解在候选空间中的分布情况，使得满足要求的解不再是极少数，而是占据更大的 “可行空间” 。这些条件并不会直接告诉我们答案是什么，但会显著提高某些候选对象成为解的可能性。

一旦出现这种情况，完整枚举虽然仍然是可行的做法，却不再是唯一合理的选择。由于真正有价值的候选对象在整体中出现得更加频繁，我们就可以考虑放弃系统性的遍历，转而通过随机抽样的方式来接触这些关键对象，从而以更低的代价获得足够的信息。

随机化优化枚举的核心思想正是如此：**当解在候选空间中具有较高 “密度” 时，随机枚举本身就能够以较高概率命中解或与解强相关的结构** 。因此，只需对随机选取的少量候选情况进行验证，就有可能覆盖原本需要大量枚举才能遇到的关键情况。这种方法并未削弱判定的严格性，而是用概率意义上的覆盖，取代了确定性的全面遍历。

需要注意的是，随机化优化枚举并非在任何问题中都适用。若题目并未提供足以改变解分布的条件，目标对象在候选空间中仍然极为稀疏，则随机抽样往往难以奏效，完整枚举仍然不可避免。只有当题目中的特殊条件实质性地扩大了解的 “可见范围” ，随机化才能发挥出应有的效果。

总体来看，随机化优化枚举是一种 **建立在题目结构之上的枚举替代策略** 。当题目中的特殊条件使得满足要求的解在候选空间中具有 **较高出现概率或较大分布占比** 时，采用随机抽样替代系统性枚举，能够在高概率意义下覆盖关键候选情况，从而在保证正确性的同时显著降低实际运行复杂度。

## 寻找过半点直线

[题目链接](https://atcoder.jp/contests/abc422/tasks/abc422_e)

### Problem Statement

在二维平面上有 $N$ 个点，其中 $N$ 为奇数。第 $i$ 个点位于 $(x_i, y_i)$ 。所有点的坐标两两不同（不会重复）。你的任务是判断是否存在一条 **直线** ，使得这条直线 **经过严格超过一半的点**（即至少 $\lceil N/2+1 \rceil$ 个点）。

如果存在这样的直线，则根据题目条件，这条直线必定可以表示成整数系数的线性方程：

$$
a x + b y + c = 0

其中 $a, b, c$ 均为整数，且满足：

* $-10^{18} \leq a, b, c \leq 10^{18}$
* $(a,b,c) \neq (0,0,0)$

你需要输出这样的一组 $(a,b,c)$ 。如果不存在这样的直线，则输出 `No` 。

注意：如果有多条符合条件的直线，输出任意一条即可。

### Constraints

- $3 \leq N \leq 5 \times 10^5$ 且为奇数
- $-10^8 \leq x_i, y_i \leq 10^8$
- 所有点的坐标互不相同，所有输入均为整数

### Input

> $N$
> 
> $x_1 \quad y_1$
> 
> $x_2 \quad y_2$
> 
> $\ldots$
> 
> $x_N \quad y_N$

### Output


如果存在这样的直线，则输出两行：
