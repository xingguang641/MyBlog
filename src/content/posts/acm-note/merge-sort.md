# 归并排序基本原理

1945 年，约翰·冯·诺依曼（John von Neumann）首次提出了归并排序算法。作为 **分治（Divide and Conquer）思想在排序问题上的经典应用** ，它在算法理论和实际工程中都具有重要意义。归并排序的核心理念可以概括为 **“分而治之，治而合之”** 。在排序过程中，算法首先不断将原始序列拆解为更小的子序列，**直到每个子序列只包含一个元素为止** 。由于 **单个元素本身就具有天然有序性** ，这一步实际上完成了所有局部子问题的最小化。

当拆分过程结束后，算法便进入 **归并阶段** 。在这一阶段中，程序会从递归的底部开始，将已经有序的子序列两两合并，并在合并时通过比较操作保证结果依旧有序。随着合并任务逐层向上推进，多个局部有序解逐渐汇聚为一个完整的全局有序序列，从而完成整个排序过程。得益于这一 **严谨且结构化的流程** ，归并排序能够保证 **排序稳定性** ，即相同元素的相对顺序不会发生改变。同时它也非常适合用于 **外部排序场景** ，如处理数据量巨大到无法一次性加载进内存的任务。归并排序不仅是理解分治思想的最佳范例之一，也是 **现代高效排序算法的重要理论基础** 。

## 排序算法图解

为了更清晰地理解归并排序的 **整体思路及执行细节** ，我们将从一个具体的初始数列 $[8,4,5,7,1,3,6,2]$ 开始，沿着算法 **实际运行的轨迹** ，通过图示依次展示它在 **不断拆分与逐层合并** 过程中的变化。借助这样的 **可视化展开** ，我们不仅能看到序列如何被递归地划分成更小的部分，也能直观理解这些部分又是怎样一步步重新组合成一个完全有序的结果。

### 递归拆分阶段

归并排序首先会从 **整体入手** ，将序列逐步对半拆分，就像不断把问题往更小的局部压缩。这个拆分过程呈现出一棵 **自顶向下展开的二叉树结构** ，每次递归都把当前序列分成两个规模更小的子序列。当序列被拆分到 **只剩一个元素** 时，便不再继续。因为单个元素可以视为 **天然有序** ，这也意味着递归来到了最底层。整个拆分过程的深度大约为 $logn$ ，随着递归的不断深入，原本完整的数据被切割为许多个最微小的 “基本单位” 。

![归并排序图像](src\content\posts\acm-note\归并排序1.png)

### 有序合并阶段

当拆分不再继续时，算法开始 **反向回溯** ，此时每一步返回都伴随着 “合并” 操作的发生。两个分别 **已排序的子序列** 将被重新组合成一个更大的有序序列。合并时使用类似 “双指针” 的方式，从两个序列的开头开始比较大小，每次选择较小的元素加入结果中，然后将相应指针向前移动。随着比较逐渐推进，所有元素都会以 **从小到大的顺序重新归位** 。

![归并排序图像](src\content\posts\acm-note\归并排序2.png)

在上图示例的最后一次合并中，两个长度为四的有序子序列 $[4,5,7,8]$ 和 $[1,2,3,6]$ 会依次比较并重组，最终得到全局排好序的结果 $[1,2,3,4,5,6,7,8]$ 。整个排序过程就是在这样的 “自底向上合并” 中逐渐完成的，局部的有序不断向外扩散，直到还原为完整序列。

这个优雅的过程展示了分治思想的精髓：将复杂问题拆分为简单问题，解决后再完美组合。无论数据初始状态如何混乱，归并排序都能以稳定且可靠的方式将其整理为正确的有序形式。

# 归并排序代码讲解

为了更清晰地理解算法的执行过程，我们将从整体框架出发，分析程序如何通过递归贯彻 “分而治之” 的思想，并在合并阶段将分散的小片段重新组合成一个有序数组。下面先来看代码的基本实现：

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;

void merge(int l, int r, int mid, int *a){
    int b[r - l + 1]; 
    int i = l, j = mid + 1, k = 0;

    while (i <= mid && j <= r){
        if (a[i] <= a[j]) b[k++] = a[i++];
        else b[k++] = a[j++];
    }
    while (i <= mid) b[k++] = a[i++];
    while (j <= r) b[k++] = a[j++];

    for (int i = 0; i < r - l + 1; i++){
        a[l + i] = b[i];
    }
}

void merge_sort(int l, int r, int *a){
    if (l == r) return;

    int mid = (l + r) / 2;
    merge_sort(l, mid, a);
    merge_sort(mid + 1, r, a);
    merge(l, r, mid, a);
}
```

## 递归结构解析

在学习归并排序时，许多人虽然能够写出代码，却没有真正理解 **递归为何能够逐层收敛** 。本节将从 **区间划分的角度** 出发，把这一过程的 **核心机制** 彻底讲清楚，使逻辑不再停留在记忆层面，而是能够真正掌握其中的含义。

递归函数的关键就在 **区间划分** ，而区间划分的关键就在 **计算中点 $mid$** 上。关于 $mid$ 的计算方式可以分为 **上取整和下取整** 两种方式，而上取整与下取整的差别，背后对应着 **两套完全不同的区间收敛路径** 。一个看似简单的选择，决定了 **子区间能否持续缩小** ，也直接影响 **递归能否正确终止** 。接下来，我们就从 $mid$ 不同的计算方式入手，理解归并排序 **真正合理且稳定的划分方式** 。

### 情况一：下取整

我们直接考虑极限情况，当区间已经缩小到只有两个元素，即 $r = l + 1$ 时，根据公式可以得到：

$$
\displaystyle mid = \left\lfloor \frac{l + r}{2} \right\rfloor = \left\lfloor l + \frac{1}{2} \right\rfloor = l
$$

这意味着当左右端点相邻时 $mid$ 会与左端点重合。为了确保区间能够继续被有效划分，我们将区间切分为：

- 左区间 $[l, mid]$
- 右区间 $[mid + 1, r]$

这样无论如何，两个区间最终都能各自缩小到一个元素。因此在代码中常见这样的写法：

```cpp showLineNumbers
merge_sort(l, mid, a);
merge_sort(mid + 1, r, a);
```

如果我们尝试将区间划分成 $[l, mid]$ 和 $[mid, r]$ ，那么在 l 与 r 相邻时，得到的区间就会变为 $[l, l]$ 和 $[l, r]$ ，我们会发现右边的区间始终都是 $[l, r]$ 从而陷入死循环。

当区间已经缩小到只一个元素，即 $l == r$ 时，根据公式我们可以得到：

$$
\displaystyle mid = \left\lfloor \frac{l + r}{2} \right\rfloor = \left\lfloor l \right\rfloor = l
$$

如果按照之前的区间划分方式，我们会得到 $[l, l]$ 和 $[l + 1, l]$ 两个区间。左边的区间会进入无限循环状态，而右边的区间则直接进入非法状态。为了避免这种情况发生，我们需要在函数中明确阻止递归进入单元素区间，于是代码中加入了：

```cpp showLineNumbers
if (l == r) return;
```

这一判断确保递归在区间缩小到单个元素时能够正确终止，从而保证整个归并排序过程安全而稳定。

### 情况二：上取整

我们依旧考虑极限情况，当区间已经缩小到只有一个元素，即 $l = r$ 时，根据公式可以得到：

$$
\displaystyle mid = \left\lceil \frac{l + r}{2} \right\rceil = \left\lceil l + \frac{1}{2} \right\rceil = l + 1 = r
$$

这意味着当左右端点相邻时 $mid$ 会与右端点重合。为了确保区间能够继续被有效划分，我们将区间切分为：

- 左区间 $[l, mid - 1]$
- 右区间 $[mid, r]$

这样无论如何，两个区间最终都能各自缩小到一个元素，符合归并排序的设计预期。

跟上取整的情况类似，如果我们尝试将区间划分成 $[l, mid]$ 和 $[mid, r]$ ，那么在 l 与 r 相邻时，得到的区间就会变为 $[l, r]$ 和 $[r, r]$ ，我们会发现左边的区间始终都是 $[l, r]$ 从而陷入死循环。

当区间已经缩小到只一个元素，即 $l == r$ 时，根据公式我们可以得到：

$$
\displaystyle mid = \left\lceil \frac{l + r}{2} \right\rceil = \left\lceil r \right\rceil = r
$$

跟上取整的情况类似，我们会得到 $[r, r -  1]$ 和 $[r, r]$ 两个区间。右边的区间会进入无限循环状态，而左边的区间则直接进入非法状态，因此我们同样要禁止代码进入 $l == r$ 的状态。

## 合并结构解析

归并排序的核心不仅在于 **递归拆分区间** ，更在于 **如何将拆开的子区间重新合并为有序数组** 。理解这一点有助于我们掌握归并排序 **“分而治之” 思想的完整闭环** 。

在每一次递归返回时，两个子区间已经各自排好序，但整体仍然是分散的。**合并函数的任务** ，就是通过比较两个子区间的元素，将它们按大小顺序依次放入一个临时数组中。具体来说，我们从两个子区间的起点开始，依次比较当前元素的大小，将较小的元素放入临时数组，并向前推进对应的指针。这个过程一直持续到其中一个子区间被完全取出为止。随后，将另一个子区间剩余的所有元素直接追加到临时数组末尾。最后，将临时数组的内容复制回原数组对应的位置，**完成一次完整的归并** 。

```cpp showLineNumbers
while (i <= mid && j <= r){
    if (a[i] <= a[j]) b[k++] = a[i++];
    else b[k++] = a[j++];
}
while (i <= mid) b[k++] = a[i++];
while (j <= r) b[k++] = a[j++];
```

这种合并策略保证了两个 **已排序的子区间** 能够 **高效、稳定地** 组合成更大的有序区间。值得注意的是，**临时数组的大小** 总是等于待合并区间的长度，而 **每次合并的时间复杂度为 $O(n)$** ，其中 $n$ 为当前区间的长度。由于归并排序的 **递归深度为 $logn$** ，整体的 **时间复杂度为 $O(nlogn)$** ，这也是归并排序能够保持高效的原因之一。

通过理解 **递归的拆分逻辑和合并机制** ，我们就能清楚地看到归并排序的整体流程：每次递归都在 **缩小问题规模** ，而每次合并则在 **逐步恢复全局顺序** 。正是这种 **“分而治之” 的思想** ，使得归并排序既稳定又高效，并且能够处理任意长度的数组而无需依赖额外的复杂操作。

# 归并分治基本原理

对于多维偏序问题，常见的处理方式是先对其中一个维度进行排序，以此固定该维度上的相对顺序，从而实现降维并简化问题。然而，这种排序手段 **通常只能使用一次**：在二维偏序问题中尚能较为从容地解决，而当维度扩展到三维及更高时，单次排序已不足以同时维护多个维度之间的偏序关系。**归并分治正是在这一背景下被引入的一种方法** ，它借助分治结构，在算法流程中自然地引入顺序约束，从而隐式地维护多维偏序关系。

归并分治的关键性质在于：**它能够在不影响统计完整性的前提下，间接实现对两个维度的排序** 。在分治过程中，元素被划分为左右两部分，由于划分本身建立在第一个维偏序关系之上，因此在合并阶段，左半部分中的所有元素在第一维偏序上必然不大于右半部分中的元素，**第一维的偏序关系在结构层面已经被保证** 。

基于这一事实，在合并阶段可以将左右两部分视为在第一维上有序的两个整体。只要不改变元素所属的分治区间，左右两部分内部的元素可以任意重排而不破坏第一维上的偏序约束，因此可以在合并阶段进一步按照第二维进行排序或扫描，**这正是归并分治能够同时处理两个维度偏序关系的原因** 。

在统计贡献时，归并分治依赖方向性的约束。如果在合并阶段仅计算左侧元素对右侧元素的贡献，则对于任意一个元素而言，其最终累计的正是所有位于其左侧的元素对自身产生的影响。由于任意一对满足 “左在前、右在后” 的元素，**必然会在某一层分治中恰好被统计一次** ，因此不会遗漏或重复。

## CDQ 分治简介

CDQ 分治 **本质上就是归并分治在多维偏序问题中的直接应用** 。它并未引入新的分治思想，而是利用归并分治在合并阶段天然具备的顺序约束，使得在不额外排序多个维度的情况下，能够完成多维偏序关系的统计。因此 CDQ 分治更多是一种 **问题建模方式与统计框架** ，而非独立于归并分治之外的全新算法。

在实际应用中，CDQ 分治最常见于 **三维偏序类问题** 。这类问题通常可以通过固定一维顺序，并在分治合并过程中，借助数据结构对另外两维进行统计，从而在可接受的时间复杂度内完成计算。典型例题包括：

* 三维点对计数（如满足 $x_1 \le x_2, y_1 \le y_2, z_1 \le z_2$ 的点对数量）
* 动态序列中的偏序统计问题，如带时间维度的逆序对或贡献统计
* 若干经典竞赛题中出现的 “离线 + 树状数组 + 分治” 结构问题

从这一角度看，CDQ 分治并不是对归并分治的 “扩展” ，而是 **对其合并阶段能力的充分利用** 。只要问题能够被抽象为 “在分治结构下进行单向贡献统计” ，便往往可以自然地转化为 CDQ 分治模型。

# 偏序数对题目收集

多维偏序问题中，有相当一部分可以归结为 **偏序数对的计数问题** 。这类问题通常要求统计满足若干维度上大小关系约束的元素对数量，例如在二维或三维空间中，统计所有在各维度上同时满足不等式条件的点对。由于偏序关系本身不具备全序结构，直接枚举往往会导致不可接受的时间复杂度，因此这类题目通常需要借助离线处理与结构化算法来完成。

在算法竞赛与工程实践中，偏序数对问题具有极高的代表性。一方面，它们是多维偏序建模的最直接形式，能够清晰地反映不同维度约束之间的相互作用；另一方面，许多看似不同的问题在抽象后，往往都可以转化为偏序数对的统计，从而统一到同一类解法框架之下。因此，对这类题目的系统整理，有助于理解多维偏序问题的共性结构，并为后续算法选择与优化提供依据。

## 计算数组的小和

[题目链接](https://www.nowcoder.com/practice/edfe05a1d45c4ea89101d936cac32469)

### Problem Statement

数组小和的定义：$\displaystyle \sum_{i=1}^{n}f_i$ ，其中 $f_i$ 的定义是第 $i$ 个数左侧小于等于 $s_i$ 的个数。

例如，数组 $s = [1, 3, 5, 2, 4, 6]$

- 在 $s[0]$ 的左边小于或等于 $s[0]$ 的数的和为 $0$

- 在 $s[1]$ 的左边小于或等于 $s[1]$ 的数的和为 $1$

- 在 $s[2]$ 的左边小于或等于 $s[2]$ 的数的和为 $1 + 3 = 4$

- 在 $s[3]$ 的左边小于或等于 $s[3]$ 的数的和为 $1$

- 在 $s[4]$ 的左边小于或等于 $s[4]$ 的数的和为 $1 + 3 + 2 = 6$

- 在 $s[5]$ 的左边小于或等于 $s[5]$ 的数的和为 $1 + 3 + 5 + 2 + 4 = 15$

所以 $s$ 的小和为 $0 + 1 + 4 + 1 + 6 + 15 = 27$

给定一个数组 $s$  ，实现函数返回 $s$ 的小和。

### Constraints

- $0 < n \leq 10^5$
- $-100 \leq s[i] \leq 100$
- 所有输入都是整数

### Input

输入包含两行：

- 第一行包含一个整数 $N$ ，表示数组的长度。
- 第二行包含 $N$ 个整数，表示数组中的各个元素。

> $N$
> 
> $s_1 \quad s_2 \quad \ldots \quad s_N$

### Output

输出一个整数表示答案。

### Sample Input 1

```txt showLineNumbers=false
6
1 3 5 2 4 6
```

### Sample Output 1

```txt showLineNumbers=false
27
```

### Sample Input 2

```txt showLineNumbers=false
1
1
```

### Sample Output 2

```txt showLineNumbers=false
0
```

## 题目要点解析

回顾一下 **逆序对** 这道题，其本质是 “统计每个数左边比自己大的数的个数并求和” 。而本题则是 “统计每个数左侧比自己小的数的和并求和” ，二者在思路上有异曲同工之妙。因此，我们可以自然而然地想到使用 **归并分治** 来解决这类问题。

下面给出该题的具体实现代码：

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const int MAXN = 1e5 + 100;
int n; ll ans = 0;
int a[MAXN];

void merge(int l, int r, int mid, int *a){
    int b[r - l + 1];
    int i = l, j = mid + 1, k = 0;

    while (i <= mid && j <= r){
        if (a[i] <= a[j]){
            // a[i] 对右侧 [j, r] 的所有元素产生贡献
            ans += 1LL * a[i] * (r - j + 1);
            b[k++] = a[i++];
        } else {
            b[k++] = a[j++];
        }
    }

    while (i <= mid) b[k++] = a[i++];
    while (j <= r) b[k++] = a[j++];

    for (int t = 0; t < k; t++){
        a[l + t] = b[t];
    }
}

void merge_sort(int l, int r, int *a){
    if (l == r) return;

    int mid = (l + r) / 2;
    merge_sort(l, mid, a);
    merge_sort(mid + 1, r, a);
    merge(l, r, mid, a);
}

int main(){
    cin >> n;
    for (int i = 0; i < n; i++){
        cin >> a[i];
    }

    if (n > 1){
        merge_sort(0, n - 1, a);
    }

    cout << ans << "\n";
}
```

## 统计重要翻转对

### Problem Statement

给定一个数组 $nums$ ，如果 $i < j$ 且 $nums[i] > 2 * nums[j]$ 我们就将 $(i, j)$ 称作一个 **重要翻转对** 。

你需要返回给定数组中的重要翻转对的数量。

### Constraints

- 给定数组的长度不会超过 50000
- 输入数组中的所有数字都在 32 位整数的表示范围内

### Input

输入包含两行：

- 第一行包含一个整数 $N$ ，表示数组的长度。
- 第二行包含 $N$ 个整数，表示数组中的各个元素。

> $N$
> 
> $nums_1 \quad nums_2 \quad \ldots \quad nums_N$

### Output

输出一个整数表示答案。

### Sample Input 1

```txt showLineNumbers=false
5
1 3 2 3 1
```

### Sample Output 1

```txt showLineNumbers=false
2
```

### Sample Input 2

```txt showLineNumbers=false
5
2 4 3 5 1
```

### Sample Output 2

```txt showLineNumbers=false
3
```

## 题目要点解析

同样地，当我们看到 **下标有序条件**（ $i < j$ ）和 **数值有序条件**（ $nums[i] > 2 * nums[j]$ ）同时存在时，就可以从 **逆序对** 的角度去思考。对比逆序对的原题，我们会发现本题与原题的区别仅在于数值比较的条件略有变化，因此可以直接套用逆序对的代码框架进行处理。

下面给出这道题的完整实现代码：

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const int MAXN = 5e4 + 100;
int n; ll ans = 0;
ll a[MAXN];

void merge(int l, int r, int mid, ll *a){
    // 统计重要翻转对
    int j = mid + 1;
    for (int i = l; i <= mid; i++){
        while (j <= r && a[i] > 2LL * a[j]){
            j++;
        }
        ans += (j - (mid + 1));
    }

    // 正常归并排序
    ll b[r - l + 1];
    int i = l; j = mid + 1; int k = 0;

    while (i <= mid && j <= r){
        if (a[i] <= a[j]) b[k++] = a[i++];
        else b[k++] = a[j++];
    }

    while (i <= mid) b[k++] = a[i++];
    while (j <= r) b[k++] = a[j++];

    for (int t = 0; t < k; t++){
        a[l + t] = b[t];
    }
}

void merge_sort(int l, int r, ll *a){
    if (l >= r) return;

    int mid = (l + r) / 2;
    merge_sort(l, mid, a);
    merge_sort(mid + 1, r, a);
    merge(l, r, mid, a);
}

int main(){
    cin >> n;
    for (int i = 0; i < n; i++){
        cin >> a[i];
    }

    if (n > 1){
        merge_sort(0, n - 1, a);
    }

    cout << ans << "\n";
    return 0;
}
```

# 深层问题探究

1. 排序算法理论上能做到比 $O(nlogn)$ 还要快吗？

    这是一个非常经典且触及算法本质的问题。答案取决于我们 **如何定义 “排序”** 以及 **数据的特征** 。

    ### 基于比较的排序：无法突破

    对于任何 **基于比较** 的排序算法（如快速排序、归并排序、堆排序等），其核心操作是通过比较两个元素的大小来决定相对位置。对此，数学上有一个严格的结论：

    > **结论**：在最坏情况下，任意基于比较的排序算法，其时间复杂度下界为 $O(nlogn)$ 。

    对于 $n$ 个待排序元素，其全排列共有 $n!$ 种可能性。算法的每一次比较操作（ $a < b$ 吗？）本质上是将剩余的可能性空间减半。这可以抽象为一棵二叉决策树：

    - 树的叶子节点对应 $n!$ 种排列结果。
    - 树的高度 $h$ 代表比较次数。

    根据二叉树的性质，包含 $n!$ 个叶子节点的树，其高度必须满足：

    $$
    h \ge \log_2(n!)
    $$

    根据斯特林公式 $\log_2(n!) \approx nlogn$ 。因此比较排序无法在理论上快于 $O(nlogn)$ 。

    ### 非比较排序：线性时间的突破

    如果我们 **不依赖元素之间的比较** ，而是利用数据本身的特性（如整数的分布、位特征等），就可以绕过上述下界，达到线性时间复杂度 $O(n)$ 。这类算法通常被称为 **线性排序** 。

    常见的非比较排序算法如下：

    - **计数排序（Counting Sort）**
        - **时间复杂度**：$O(n + k)$ ，其中 $n$ 是元素个数，$k$ 是数据的取值范围。
        - **适用条件**：数据必须是整数，且取值范围 $k$ 不能远大于 $n$ 。
        - **算法本质**：利用数组下标的天然有序性，将数据值映射为数组下标。

    - **基数排序（Radix Sort）**
        - **时间复杂度**：$O(d \cdot (n + k))$ ，其中 $d$ 是数字的最大位数（或字符长度）， $k$ 是进制基数。
        - **适用条件**：元素为整数或定长字符串等可分割为“位”的数据。
        - **算法本质**：将整数按位数切割，从低位到高位依次进行稳定的计数排序。

    - **桶排序（Bucket Sort）**
        - **时间复杂度**：平均 $O(n + k)$ ，最坏 $O(n^2)$（取决于桶内排序算法）。
        - **适用条件**：数据在数值范围内分布均匀。
        - **算法本质**：分治思想。将数据分发到不同的桶中，桶内单独排序，最后合并。

    ### 问题总结

    虽然非比较排序理论上可以达到 $O(n)$ ，但这并不意味着它们总是比 $O(nlogn)$ 的算法更好。它们通常通过 **牺牲空间换取时间**（Space-Time Tradeoff），且对 **数据类型** 有严格限制。
