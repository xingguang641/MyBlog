# 二分查找基本原理

二分查找（Binary Search）是一种在 **有序序列** 中高效查找目标元素的经典算法。它的核心思想是：**通过不断比较当前区间的中间位置，将不可能包含目标值的一半区间直接舍弃** ，从而使搜索范围在每一步中都缩小为原来的一半。正是这种“折半搜索”的方式，使得二分查找能够在极少的比较次数内定位目标元素，大幅提升查找效率。

在长度为 $n$ 的有序数组中，顺序查找在最坏情况下需要遍历整个数组，其时间复杂度为 $O(n)$ ；而二分查找通过不断折半搜索，将查找过程压缩到对数级别，时间复杂度仅为 $O(\log n)$ 。正因为这一显著优势，二分查找在算法竞赛和工程实践中都被频繁使用，也是许多高效算法的基础工具。

二分查找一共有四种常见形式，分别用于求解：“最后一个 `< K` 的位置” 、“第一个 `≥ K` 的位置” 、“最后一个 `≤ K` 的位置” ，以及 “第一个 `> K` 的位置” 。虽然从结果上看这四种二分各不相同，但它们在代码结构上高度相似，整体框架几乎一致，差别主要体现在 **比较条件** 与 **区间收缩** 上。

因此这四种二分看似繁多，实际上理解难度并不高，代码实现也十分简洁。只要明确每一种二分最终要逼近的是哪一个 “边界” ，就可以在编写和阅读代码时避免混淆。接下来将逐一讲解这四种二分的实现方式。首先让我们从图像的角度来看一下这四种二分在有序序列中对应的位置。

## 二分代码详解

下面给出的四段代码分别对应前文提到的四种二分形式。它们在整体结构上完全一致，均采用 **闭区间 `[l, r]`** 的写法，循环条件统一为 `l <= r` 。在查找过程中，通过不断更新区间端点，使搜索区间逐步缩小，直到区间为空为止。同时，每一种二分都额外维护了一个用于保存结果的候选答案 `ans` ，用于记录当前已经找到的、满足条件的位置。

需要注意的是，这四种二分在代码框架上几乎没有区别：初始化方式、循环结构以及区间收缩形式都完全相同。它们之间真正的差异，体现在**比较条件成立时是否更新 `ans`，以及对应更新的是左边界还是右边界** 。正是这些看似细微的差别，决定了每一种二分最终返回的具体含义。

### 最后一个 < K 的位置

```cpp title="main.cpp"
int lastLess(int a[], int n, int K) {
    int l = 0, r = n - 1, ans = -1;
    while (l <= r) {
        int m = (l + r) / 2;
        if (a[m] < K) {
            ans = m;
            l = m + 1;
        } else {
            r = m - 1;
        }
    }
    return ans;
}
```

该二分用于查找 **严格小于 `K` 的最大下标** 。

* 当 `a[m] < K` 时，将当前下标 `m` 记录到 `ans` 中，并更新左边界
* 当 `a[m] >= K` 时，不更新 `ans`，并更新右边界

若最终不存在满足条件的元素，则 `ans` 保持为 `-1`，函数返回 `-1` 。

### 第一个 ≥ K 的位置

```cpp title="main.cpp"
int firstGreaterEqual(int a[], int n, int K) {
    int l = 0, r = n - 1, ans = n;
    while (l <= r) {
        int m = (l + r) / 2;
        if (a[m] >= K) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
```

该二分用于查找 **第一个大于等于 `K` 的位置** 。

* 当 `a[m] >= K` 时，将当前下标 `m` 记录到 `ans` 中，并更新右边界
* 当 `a[m] < K` 时，不更新 `ans`，并更新左边界

若不存在满足条件的元素，则 `ans` 保持为 `n`，函数返回 `n` 。

### 最后一个 ≤ K 的位置

```cpp title="main.cpp"
int lastLessEqual(int a[], int n, int K) {
    int l = 0, r = n - 1, ans = -1;
    while (l <= r) {
        int m = (l + r) / 2;
        if (a[m] <= K) {
            ans = m;
            l = m + 1;
        } else {
            r = m - 1;
        }
    }
    return ans;
}
```

该二分用于查找 **小于等于 `K` 的最大下标** 。

* 当 `a[m] <= K` 时，将当前下标 `m` 记录到 `ans` 中，并更新左边界
* 当 `a[m] > K` 时，不更新 `ans`，并更新右边界

若最终不存在满足条件的元素，则函数返回 `-1` 。

### 第一个 > K 的位置

```cpp title="main.cpp"
int firstGreater(int a[], int n, int K) {
    int l = 0, r = n - 1;
    int ans = n;
    while (l <= r) {
        int m = (l + r) / 2;
        if (a[m] > K) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
```

该二分用于查找 **严格大于 `K` 的最小下标** 。

* 当 `a[m] > K` 时，将当前下标 `m` 记录到 `ans` 中，并更新右边界
* 当 `a[m] <= K` 时，不更新 `ans`，并更新左边界

若不存在满足条件的元素，则 `ans` 保持为 `n`，函数返回 `n` 。

## 二分代码比较

从整体来看，这四种二分在写法上高度一致：初始化方式相同、循环结构相同、区间表示方式也相同。它们之间的差别并不体现在代码框架上，而集中在极少数关键细节中。对于实际编写和记忆来说，真正需要关注、也真正容易出错的地方只有两个：**一是比较条件本身以及答案 `ans` 的更新位置，二是在比较结果确定之后，搜索区间应当向哪一侧收缩** 。

先来看判断条件和答案的更新方式：

```cpp
if (a[m] < K) {
    ans = m;
}
```

既然我们要查找的是 `< K` ，那么判断条件就应当直接写成 `< K` ，而不是通过其他形式绕一层逻辑。同时，`ans` 的更新也必须放在这一判断条件内部，因为只有在 `a[m] < K` 成立时，当前位置 `m` 才是一个真实满足条件的位置，此时将其记录为候选答案是合理且安全的。

这一点在其他几种二分中也是完全一致的：**查什么条件，就在什么条件下更新答案** 。也就是说，判断语句中所写的比较关系，本身就直接对应了当前二分所要寻找的目标区间。只有当当前位置 `m` 真正满足题目要求时，才会将其记录为候选答案；而在条件不成立的情况下，则仅通过调整区间边界继续查找，而不会对答案产生任何影响。保持这种 “一一对应” 的写法，可以避免条件与结果不匹配所带来的混乱。

接下来是第二个关键点区间的收缩方向：

```cpp
if (a[m] < K) {
    ans = m;
    l = m + 1;
}
```

由于当前查找的目标是 **“最后一个 `< K` 的位置”** ，当 `a[m] < K` 成立时，我们并不会立刻停止，而是需要继续向右侧查找，看看是否还能找到下标更大的、同样满足条件的位置。因此在这种情况下，区间会向右侧收缩，即更新 `l = m + 1` ，将左半部分排除。

与之相对地，如果查找的是 **“第一个满足条件的位置”** ，那么在判断条件成立时，当前下标 `m` 虽然已经满足要求，但并不能作为最终结果直接返回。此时仍需要继续在左侧区间中查找是否存在更靠前、同样满足条件的位置。因此区间的收缩方向应当向左，通过执行 `r = m - 1` 来排除右侧区间，从而避免最终返回一个位置更靠后的下标。

# 最大值最小化问题

**最大值最小化问题** 是二分答案法最经典、也最直观的应用之一。其核心思想是：当答案存在明确的 **“可行 / 不可行” 边界** 时，我们可以将搜索从具体方案转移到 **答案空间** 本身。通过二分一个候选值，并检验在该约束下是否能够完成任务，我们便能逐步逼近使最大代价尽可能小的最优解。

这类问题的共同特征在于：只要给定一个上限，通常可以用 **贪心或模拟** 的方法判断可行性；而这种判断函数的单调性，使得 **二分答案** 成为最自然、最高效的解法。因此，无论是 **分割数组** 、**安排工作日程** ，还是将物体尽量均匀划分到若干容器中，最大值最小化问题都可以作为一个统一的分析视角，将各种题目串联到同一个框架下。

## 题目要点解析

画匠问题（Painter's Partition Problem）是最大值最小化问题中最具代表性的经典案例之一，而这类问题的标志性高效解法正是 **二分查找（Binary Search）**。之所以能够应用二分法，是基于以下转化逻辑：最大值最小化问题本质上是一个 **优化问题** ，但它巧妙地通过引入一个 **决策函数（Decision Function）**，将其转化为了一个具有 **单调性** 的 **判定问题** ，从而使二分搜索成为可能。

1. **定义判定问题**

    我们定义一个判定函数 $P(X)$ ，来回答以下问题：

    > **“我们能否在最大值不超过 $X$ 的限制下完成所有任务/满足所有条件？”**

2. **关键的单调性**

    如果 $P(X)$ 成立，那么对于任何 $X' > X$ 的值，$P(X')$ 也一定成立。

    *   **直观理解**：如果能在最长耗时 10 分钟的限制下完成工作，那么也能在最长耗时 11 分钟的限制下完成

    如果 $P(X)$ 不成立，那么对于任何 $X'' < X$ 的值，$P(X'')$ 也一定不成立。

    *   **直观理解**：如果不能在最长耗时 10 分钟的限制下完成工作，同样不能在最长耗时 9 分钟的限制下完成

3. **形成 "False-True" 序列**

    这就形成了一个关于 $X$ 的单调序列：

    $$
    \underbrace{\text{False}, \dots, \text{False}}_{\text{无法满足}}, \underbrace{\text{True}}_{\text{最优解 } X_{\text{opt}}}, \underbrace{\text{True}, \dots, \text{True}}_{\text{可以满足}}
    $$

由于这个判定函数的返回值是 **单调的**（从 $\text{False}$ 变为 $\text{True}$ ），因此我们就可以对答案的范围进行二分查找。

*   **搜索空间**：二分查找不是作用在输入数据上，而是作用在 **最终答案 $X$ 的可能取值范围 $[L, R]$** 上。
*   **搜索目标**：我们的目标是找到使 $P(X)$ **首次变为 $\text{True}$** 的那个最小值 $X_{\text{opt}}$ 。

# 离散型中位数问题

二分答案法在 **求中位数或第 $k$ 小值** 的问题中同样非常有效。对于这些静态、离线处理的场景，我们并不直接寻找答案本身，而是对 **答案的取值空间** 进行二分。每当二分到一个候选数 $x$ 时，只需统计数组中有多少元素小于或等于 $x$ ，就能判断 $x$ 是否满足第 $k$ 小值的要求。通过不断缩小搜索区间，最终即可锁定真实的中位数或第 $k$ 小值。

而在需要 **动态维护中位数** 的场景中，通常会采用 **双优先队列** 的结构：用一个最大堆维护较小的一半元素，另一个最小堆维护较大的一半元素，并保持两边规模平衡。这样，每次插入新元素后，都能迅速得到当前的中位数。

## 题目要点解析

既然二分可以解决静态中位数问题，自然也能解决静态第 $k$ 小值问题。核心思想是：我们并不直接去找数组中第 $k$ 小的元素，而是将问题转化为对答案空间的判断。具体来说，我们可以将 “查找第 $k$ 小的值” 这个优化问题，转化为如下判定问题：

> 对于某个候选值 $X$ ，判断原始数据集中小于或等于 $X$ 的元素个数是否大于或等于 $k$ 。

# 逆向分析求解问题

在算法竞赛中，许多题目如果正向求解往往比较复杂甚至难以处理，这时可以考虑 **逆向求解** 。其核心思路是：假设我们已经知道一个候选答案，尝试判断该答案是否可行，即判断在这个答案下倒推题目给出的所有约束是否成立。如果这个判断过程相对简单，并且具有 **单调性**（例如，答案越大或越小，满足条件的可能性单调变化），那么就可以利用 **二分答案法** 来逆向求解问题。

通过这种思路，我们不再直接构造复杂的解法，而是从可能的答案出发，逐步缩小搜索空间，最终找到符合题目要求的最优解。这种逆向思考在许多最值问题和约束优化题中都非常常见，也是竞赛中常用的解题套路之一。

## 刀砍毒杀怪兽

[题目链接](https://github.com/algorithmzuo/algorithm-journey/blob/main/src/class051/Code07_CutOrPoison.java)

### Problem Statement

怪兽的初始血量是一个整数 $hp$ ，给出每一回合刀砍和毒杀的数值 $cuts$ 和 $poisons$ 。

第 $i$ 回合如果用刀砍，怪兽在这回合会直接损失 $cuts[i]$ 的血，不再有后续效果；第 $i$ 回合如果用毒杀，怪兽在这回合不会损失血量，但是之后每回合都损失 $poisons[i]$ 的血量，并且所有毒杀效果可以叠加。

两个数组 $cuts$ 、$poisons$ ，长度都是 $n$ ，代表你一共可以进行 $n$ 回合。每一回合你只能选择刀砍或者毒杀中的一个动作，如果你在 $n$ 个回合内没有直接杀死怪兽，意味着你已经无法有新的行动了。但是怪兽如果有中毒效果的话，那么怪兽依然会在血量耗尽的那回合死掉。

返回至少多少回合，怪兽会死掉。

### Constraints

- $1 \leq n \leq 10^5$
- $1 \leq hp \leq 10^9$
- $1 \leq cuts[i], poisons[i] \leq 10^9$

### Input

输入包含三行：

- 第一行包含两个个整数 $n$ 和 $hp$ 。
- 第二行包含 $n$ 个整数，表示 $cuts$ 数组中的元素。
- 第三行包含 $n$ 个整数，表示 $poisons$ 数组中的元素。

> $n \quad hp$
>
> $cuts_1 \quad cuts_2 \quad \ldots \quad cuts_n$
>
> $poisons_1 \quad poisons_2 \quad \ldots \quad poisons_n$

### Output

输出一个整数表示答案。

## 题目要点解析

我们先直接来看问题本身：这道题的关键难点在于 **毒杀伤害具有不确定性** 。刀砍造成的伤害是固定值，而毒杀的伤害会随着回合数累积，因此在不知道最终需要多少回合击杀怪物的情况下，我们无法简单判断 “当前回合选择刀砍还是毒杀更划算” 。但如果我们 **提前知道最终需要的总回合数** ，那么毒杀在这段固定长度内能造成的总伤害就变成了一个确定值。

更重要的是，这个 “能否在 $T$ 回合内击杀怪物” 的判断具有天然的 **单调性**：

* 要求的回合越短，条件越苛刻，更难达成
* 回合越长，可累积的毒杀伤害越多，自然越容易满足

既然存在这样的单调性质，我们就可以利用 **二分答案** 来直接搜索最小可行的回合数。整体策略就是：猜一个回合数 $T$，判断能否在 $T$ 回合内击杀怪物，根据结果缩小区间，直到找到最小的可行值。

## 可安排的任务数

[题目链接](https://leetcode.cn/problems/maximum-number-of-tasks-you-can-assign/description/)

### Problem Statement

给你 $n$ 个任务和 $m$ 个工人。

每个任务需要一定的力量值才能完成，需要的力量值保存在下标从 0 开始的整数数组 $tasks$ 中，第 $i$ 个任务需要 $tasks[i]$ 的力量才能完成。每个工人的力量值保存在下标从 0 开始的整数数组 $workers$ 中，第 $j$ 个工人的力量值为 $workers[j]$ 。

每个工人只能完成 **一个** 任务，且力量值需要 **大于等于** 该任务的力量要求值（即 $workers[j] >= tasks[i]$ ）。

除此以外，你还有 $pills$ 个神奇药丸，可以给 **一个工人的力量值** 增加 $strength$ 。你可以决定给哪些工人使用药丸，但每个工人 **最多** 只能使用 **一片** 药丸。

给你下标从 0 开始的整数数组 $tasks$ 和 $workers$ 以及两个整数 $pills$ 和 $strength$ ，请你返回 **最多** 有多少个任务可以被完成。

### Constraints

- $n == tasks.length$
- $m = workers.length$
- $1 \leq n, m \leq 5 * 10^4$
- $0 \leq pills \leq m$
- $0 \leq tasks[i], workers[j], strength \leq 10^9$

### Input

输入包含三行：

- 第一行包含四个整数 $n$ 、$m$ 、$pills$ 和 $strength$ 。
- 第二行包含 $n$ 个整数，表示 $tasks$ 数组中的元素。
- 第三行包含 $m$ 个整数，表示 $workers$ 数组中的元素。

> $n \quad m \quad pills \quad strength$
>
> $tasks_1 \quad tasks_2 \quad \ldots \quad tasks_n$
>
> $workers_1 \quad workers_2 \quad \ldots \quad workers_m$

### Output

输出一个整数表示答案。

### Sample Input 1

```txt showLineNumbers=false
3 2 1
0 3 3
```

### Sample Output 1

```txt showLineNumbers=false

```


```txt showLineNumbers=false

```



## 题目要点解析

首先思考一下这道题的简单版本：假设 $tasks$ 数组和 $works$ 数组都是有序的，并且不存在大力药丸。那我们就可以直接用 **双指针匹配** 的思路来解决：如果当前工人的力量能够完成当前任务，就让他做该任务，否则跳过这个工人。整个过程就是工人与任务 **按顺序逐一配对** 。

在重新加入大力药丸之后，我们很容易会想到继续沿用先前的双指针策略：如果一个工人可以做当前的的任务，我们就让这个工人做当前的任务；如果不可以，我们就尝试让该工人吃药，再尝试完成当前的任务。这一思路看似合理，但其实是 **错误的** ，原因在于：当工人吃药之后，他在全体工人中的相对排序也随之改变。既然实力变强，他理论上就应该去承担更高难度的任务，而不再适合停留在原本的任务位置。

为了解决这个问题，我们可以尝试一个更合理的贪心：当一个工人能够胜任多个任务时，让他去完成 **他能力范围内最困难的任务** 。这是因为困难的任务可供选择的工人本来就更少，因此应当优先分配。可以轻易证明这个策略比按顺序逐一配对的思路更优。

这就是所谓的 “解锁任务” 的思路：对于每个工人，我们把所有他能做的任务加入一个任务集合，并优先分配其中最难的任务。如果当前工人完全做不了任务，那就让他吃药，再尝试解锁任务；如果仍无法完成，则撤销药丸并继续尝试下一个工人。

不过这条看似严谨的贪心策略依然是 **错误的**：如果工人的能力数组为 $[2,3,4]$ ，任务的难度数组为 $[3,8,9]$ ，药丸只有一个并且药效为 `+5` 点能力值。那么我们直接给第一个工人吃药就只能做一个任务，而给第三个工人吃药则可以做两个任务。也就是说我们无法确定哪个工人一定得吃药。

但如果我们事先就知道要完成的任务数量 $ans$ 情况就会变得明确。根据自然智慧，我们选择难度最低的 $ans$ 个任务，选择能力最大的 $ans$ 个工人。由于我们一定要完成 $ans$ 个任务，也就是每个被选中的工人都必须完成一个任务。因此在某个工人不吃药就无任务可做的情况下，我们就必须让他吃药。这样一来，我们就解决了正向思路中 “究竟该不该给某个工人吃药” 这一难以判断的问题。

同样道理，这里的 “工人能否完成 $T$ 个任务” 的判断具有天然的 **单调性**：

* 要求的任务越多，条件越苛刻，自然更难达成
* 要求的任务越少，条件越轻松，自然容易满足

## 打家劫舍IV问题

[题目链接](https://leetcode.cn/problems/house-robber-iv)

### Problem Statement

沿街有一排连续的房屋。每间房屋内都藏有一定的现金。现在有一位小偷计划从这些房屋中窃取现金。

由于相邻的房屋装有相互连通的防盗系统，所以小偷 **不会窃取相邻的房屋** 。

小偷的 **窃取能力** 定义为他在窃取过程中能从单间房屋中窃取的 **最大金额** 。

给你一个整数数组 `nums` 表示每间房屋存放的现金金额。形式上，从左起第 `i` 间房屋中放有 `nums[i]` 美元。

另给你一个整数 `k` ，表示窃贼将会窃取的 **最少** 房屋数。小偷总能窃取至少 `k` 间房屋。

返回小偷的 **最小** 窃取能力。

### Constraints

- $1 \leq n.length \leq 10^5$
- $0 \leq nums[i] \leq 10^9$
- $0 \leq k \leq (nums.length + 1) / 2$

### Input

输入包含两行：

- 第一行包含两个整数 $n$ 和 $k$ 。
- 第二行包含 $n$ 个整数，表示数组的元素。

> $n \quad k$
>
> $nums_1 \quad nums_2 \quad \ldots \quad nums_n$

### Output

输出一个整数表示答案。

### Sample Input 1

```txt showLineNumbers=false
4 2
2 3 5 9
```

### Sample Output 1

```txt showLineNumbers=false
5
```

### Sample Input 2

```txt showLineNumbers=false
5 2
2 7 9 3 1
```

### Sample Output 2

```txt showLineNumbers=false
2
```
