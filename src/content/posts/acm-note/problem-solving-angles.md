# 复杂度分析思维

分析复杂度是十分重要的，因为一个一模一样的题面，但数量级的不同会导致做法完全不同，不同的做法之间的思考难度以及实现难度可能天差地别，如果不考虑时间复杂度直接对着题目想最优解是愚蠢的做法。

数量级指的是程序要处理的任务数量而不是数值，比如背包 DP 中物品数是量级，而重量是数值，我们分析复杂度分析的是数量级而不是数值，虽然数值的不同也会导致解法的不同，但大多数情况只是做特殊处理，对做法本身不会有太多的影响（除了同余最短路这些特殊问题）

## 低量级数据

n = 8 一眼排列量级（说明题目非常暴力，可能要求你枚举所有排列）

n = 20 一眼状压 DP 量级

n = 40 一眼折半搜索量级

## 中量级数据

n = 10^3/10^4 一眼平方量级

n = 10^5 一眼 nlogn 量级（排序、二分、分治）

n = 10^8/10^9 一眼线性量级

## 高量级数据

n > 10^9 线性无法解决，一定要用到优化技巧，优化技巧一定是数学技巧（整除分块、矩阵快速幂、数学公式）

## 题目方面

要从 n = 1 k = 1 的基础情况开始分析，有时候就会发现很多数学规律，从而快速解出这些题（要用到数学归纳法的题目常见的也就是数学题）

## 样例方面

严格意义上这个不算是数学归纳法，而是为了与一般的数学归纳法作出区分特意在此说明。有些题目已经规定了 n = 1000，但你仍然要从 n = 1 开始推导，也就是复杂情况是从简单情况推导而来的，常见的题目类型就是 “增量法” 类型的题目。或者说是题目要求你在棋盘中放下 100 个棋子然后最大化得分什么的，然后你可以从最大化一个棋子开始分析，最终发现最大化 2 个棋子只需要在最大化 1 个棋子的情况下多放一个棋子，最后递推得到 100 个棋子的情况
