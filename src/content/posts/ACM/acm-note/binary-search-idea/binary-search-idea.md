# 二分查找基本原理

二分查找（Binary Search）是一种基于 **分治思想** 的经典检索算法，专门用于在 **有序序列** 中快速定位目标元素或特定边界。其核心逻辑建立在序列的单调性之上：通过对当前搜索区间中点的持续评估，算法能够根据中点值与目标值的逻辑关系，果断排除掉不包含解的半数区间。这种 “折半搜索” 的机制，使得搜索空间在每一轮迭代中均以指数级速度收缩，从而在海量数据中实现近乎瞬时的精准锁定。相较于逐一比对的穷举法，二分查找将问题的规模转化为了对数级的步数，是处理大规模静态数据时最有效的策略之一。

在规模为 $n$ 的有序数组中，传统的顺序查找在最坏情况下需遍历整个序列，时间复杂度为 $O(n)$ ，而二分查找通过对数级的区间压缩，将复杂度优化至 $O(\log n)$ 。这意味着即便数据规模从百万级跃升至十亿级，查找步数也仅是从 $20$ 次增加到 $30$ 次左右。凭借这一显著的性能优势，二分查找不仅是算法竞赛中的核心工具，更是现代工程实践中构建高效索引与检索系统的基石。

在实际应用中，二分查找通常演化为四种标准形式，分别用于界定不同的逻辑边界：“最后一个 $< K$ 的位置” 、“第一个 $\geq K$ 的位置” 、“最后一个 $\le K$ 的位置” 以及 “第一个 $> K$ 的位置” 。尽管各形式的语义侧重不同，但其代码实现高度同构。从代数构造的角度审视，各版本之间的核心差异仅在于 **比较条件的选取** 与 **区间收缩策略的定义** 。从数轴分布的角度审视，这些变体本质上是在有序序列中寻找满足特定性质的 **临界分割点** 。

这四种变体看似繁杂，实则逻辑统一。理解的核心在于识别判定准则在序列中产生的 **分段属性** ，从而明确算法最终所逼近的临界点位置。通过对指针移动逻辑的精准控制，我们可以将复杂的区间搜索抽象为对目标边界的精准锚定。接下来我们将从直观分布与代码实现两个维度，逐一解析这四种二分模式的构造细节，并深入探讨如何通过统一的思维模型来规避常见的问题。

## 二分代码详解

下文给出的四段代码分别对应前文所述的四种二分检索形式。为了确保 **逻辑的严谨性** 与 **实现的一致性** ，这些模型统一采用 **闭区间 $[l, r]$** 的标准定义，并将 **循环终止条件** 严格界定为 `l <= r` 。在检索过程中，算法通过对区间中点的持续评估来驱动 **左右边界的交替收缩** ，使搜索空间在每一轮迭代中精确减半，直至区间完全耗尽为止。为了稳健地锁定目标位置，每种实现均引入了 **辅助变量 ans** ，其核心作用是在满足判定条件时实时暂存当前的候选坐标。这种设计确保了在循环结束、搜索空间收敛为空集后，算法依然能够可靠地输出最后一次符合 **约束要求** 的有效索引。

从代码构造的视角审视，这四类变体在 **初始化逻辑** 、**迭代步长** 以及 **区间折半** 的计算方式上表现出高度的同质化，整体框架几乎完全重合。这种结构上的高度统一意味着我们只需掌握一套 **核心模板** ，即可通过微调局部逻辑来适配不同的边界检索需求。其本质的差异化特征仅集中于两点：**判定条件的具体选择** ，以及在条件达成时 **对搜索方向（左、右边界）的收缩决策** 。正是这些看似细微的逻辑扰动，决定了算法指针最终会向有序序列中的哪一类 **临界位置** 进行偏移，并最终在 ans 中沉淀出精确的目标含义。

### 最后一个 < K 的位置

```cpp title="main.cpp"
int lastLess(int a[], int n, int K) {
    int l = 0, r = n - 1, ans = -1;
    while (l <= r) {
        int m = (l + r) / 2;
        if (a[m] < K) {
            ans = m;
            l = m + 1;
        } else {
            r = m - 1;
        }
    }
    return ans;
}
```

该二分用于查找 **严格小于 K 的最大下标** 。

* 当 `a[m] < K` 时，将当前下标 `m` 记录到 `ans` 中，并更新左边界
* 当 `a[m] >= K` 时，不更新 `ans` ，并更新右边界

若最终不存在满足条件的元素，则 `ans` 保持为 `-1` ，函数返回 `-1` 。

## 二分代码比较

从上面的代码详解可以看出，这四种二分形式在实现层面表现出高度的 **同构性**：其 **初始化逻辑** 、**循环控制结构** 以及 **闭区间表示方式** 完全一致。代码框架的稳定性意味着，实际编写中的认知负担并非源于结构，而集中于极少数 **决定性细节** 。在实现与记忆过程中，真正关乎算法正确性且最易产生偏差的逻辑仅有两点：其一是 **判定条件的确立与候选答案 ans 的更新时机** ；其二是当判定条件达成后，**搜索区间应当向哪一侧进行收缩** 。

先来看判断条件和答案的更新方式：

```cpp
if (a[m] < K) {
    ans = m;
}
```

既然我们要查找的是 `< K` ，那么判断条件就应当直接写成 `< K` ，而不是通过其他形式绕一层逻辑。同时，`ans` 的更新也必须放在这一判断条件内部，因为只有在 `a[m] < K` 成立时，当前位置 `m` 才是一个真实满足条件的位置，此时将其记录为候选答案是合理且安全的。

这一点在其他几种二分中也是完全一致的：**查什么条件，就在什么条件下更新答案** 。也就是说，判断语句中所写的比较关系，本身就直接对应了当前二分所要寻找的目标区间。只有当当前位置 `m` 真正满足题目要求时，才会将其记录为候选答案；而在条件不成立的情况下，则仅通过调整区间边界继续查找，而不会对答案产生任何影响。保持这种一一对应的写法，可以避免条件与结果不匹配所带来的混乱。

接下来是第二个关键点区间的收缩方向：

```cpp
if (a[m] < K) {
    ans = m;
    l = m + 1;
}
```

由于当前查找的目标是 **“最后一个 $< K$ 的位置”** ，当 `a[m] < K` 成立时，算法并不会立即停止，而是需要继续向右侧探测，以验证是否还存在下标更大且同样满足条件的位置。因此，在这种情况下，搜索区间会 **向右侧收缩** ，即通过执行 `l = m + 1` 来排除左半部分，驱动指针向后偏移。

与之相对，若目标是锁定 **“第一个满足条件的位置”** ，即便当前下标 $m$ 已符合要求，也无法将其作为最终结果直接返回。此时仍需在左侧区间内持续逼近，以确认是否存在更靠前、索引更小的合规位置。因此，区间的收缩方向应当 **向左偏移** ，通过执行 `r = m - 1` 来排除右侧冗余空间，从而确保最终能锚定在最左端的边界上。

总的来说，这种边界处理的直觉核心在于：**求解最后一个数则向后搜索，求解第一个数则向前搜索** 。通过这种基于目标方位的动态调整，可以确保算法在复杂的区间波动中，始终能够稳定地锚定在预期的临界点上。这种逻辑不仅从根本上消除了返回位置偏移的风险，也让抽象的边界处理回归到了直观的线性推导中，是构建工业级健壮二分逻辑的基石。

# 最大值最小化问题

**最大值最小化问题** 是二分答案法最经典且最直观的应用之一。其核心思想在于，当方案的最优解存在明确的可行与不可行边界时，我们可以将搜索重心从寻找具体方案转移到对 **答案空间** 本身的判定。通过二分一个候选值作为约束上限，并检验在该约束下是否能够完成任务，我们便能逐步逼近使最大代价尽可能小的最优解。这种方式规避了直接构造最优解的复杂性，将其转化为了一系列简单的存在性判定。

从理论本质上看，最大值最小化问题一定可以用二分来解决。我们可以设定一个 **虚拟上界** ，只要能通过策略调整让所有元素都小于这个上界，那么系统的最大值就必然被压制在这个上界之内。如果我们不断尝试下压这个上界，本质上就是在执行最小化最大值的操作，直到上界被压到物理临界点而无法再下压为止。这种下压的过程，实际上是在不断收紧约束条件，逼近系统承载能力的极限。

这里涉及到一个核心逻辑，即 **单调性的不可逆转** 。我们设想一下：有没有一种可能，当下压到某个临界点 $k$ 发现不满足后，往下再压一些到 $k-1$ 反而又满足了？**这在逻辑上是绝对不成立的** 。若上界 $k$ 无法推导出可行方案，那么根据问题的 **单调性** 可以断定：所有比 $k$ 更为严苛的约束条件（如 $k-1$ 或 $k-2$ 等）也必然无法满足。这一性质构成了二分搜索的逻辑基石，即当某个前缀区间不可行时，其更受限的子空间也必然位于 **不可行域** 。

这种单调性将原本杂乱无章的方案搜索简化为了对 **临界点** 的精准定位。无论是分割数组还是安排工作日程，这种下压上界的分析视角都能将各种异构题目串联到同一个二分框架下。在实际编写代码时，我们只需要实现一个简单的贪心判定函数，利用二分查找可以在有限时间内锁定恰好可行的最小值，这便是解决此类问题的终极利器。

## 题目要点解析

画匠问题（Painter's Partition Problem）是最大值最小化领域中最具代表性的经典案例。这类问题的核心挑战在于，如何在多名画匠协作且每人只能粉刷连续木板的前提下，让耗时最长的那位画匠工作量尽可能小。解决这一问题的标志性高效方案正是 **二分查找** 。之所以能够应用二分，是因为我们巧妙地利用了一个 **决策函数** ，将复杂的 **最优化问题** 转化为了一个具备严格单调性的 **判定问题** 。

这种转化的逻辑基石在于，虽然直接构造一个完美的划分方案非常困难，但如果给定一个固定的时间上限 $X$ ，判断在 $K$ 个画匠内能否完成任务却非常简单。由于这个判定函数的返回值随 $X$ 的增大呈现出从 $\text{False}$ 到 $\text{True}$ 的 **单调演变** ，这便为二分算法提供了施展空间。只要 $X$ 足够大，任务一定可行；而一旦 $X$ 过小，任务必然失败。

*   **搜索空间**：二分查找不是作用在输入数据上，而是作用在 **最终答案 X 的可能取值范围 $[L, R]$** 上
*   **搜索目标**：我们的目标是找到使 $P(X)$ **首次变为 $\text{True}$** 的那个最小值 $X_{\text{opt}}$

通过这种 **下压上界** 的策略，我们将原本可能需要复杂动态规划才能处理的线性划分问题，转化为对数级别的 **贪心扫描** 。这种从直接 “求解最优方案” 到 “验证边界可行性” 的思维飞跃，正是二分答案法在处理 **最大值最小化** 问题时的逻辑精髓所在。它不仅简化了问题的计算维度，更利用了决策空间的单调性，将搜索效率推向了极致。

## 题目要点解析

最大值最小化题目的另一个经典就是 **路径中最大边权最小化问题** ，常见的做法就是二分或者增量法（从小边权开始加边，直到两点连通）。这一类问题的共同特点是：答案本身具有明显的 **单调性** ，当允许的最大权值越大时，可行的方案只会越来越多。因此我们往往可以通过枚举最大允许值，并判断是否存在合法方案来求解。

题目要求从城市 $1$ 走到城市 $n$ ，每经过一个城市需要支付费用 $f_i$ ，同时每条道路会消耗一定血量，而总血量损失不能超过 $b$ 。如果我们把路径中经过城市的费用最大值记为 $x$ ，那么问题就变成：**在只允许经过 $f_i \leq x$ 的城市的情况下，是否还能从 1 走到 n，并且总血量损失不超过 b** 。这时可以发现一个非常关键的性质：如果某个 $x$ 是可行的，那么任何 $x' > x$ 也一定是可行的，因为允许经过的城市只会更多，不会更少。这种明显的单调关系正好满足二分答案的条件。因此我们可以对路径中允许的最大城市费用进行二分。

在具体实现时，假设当前二分到的最大费用为 $mid$ 。我们只保留所有满足 $f_i \leq mid$ 的城市，其余城市视为不可进入。然后在这个限制下的图中，从城市 $1$ 出发计算到城市 $n$ 的最短路，边权就是道路的血量损失。如果求出的最短距离不超过 $b$ ，说明在最大费用为 $mid$ 的限制下仍然存在一条合法路径，那么这个答案就是可行的，可以继续尝试更小的费用；反之如果最短路已经超过 $b$ 或者无法到达终点，则说明当前限制过于严格，需要增大 $mid$ 。

# 离线型中位数问题

二分答案法在 **求中位数或第 k 小值** 的问题中同样非常有效。对于这些静态、离线处理的场景，我们并不直接寻找答案本身，而是对 **答案的取值空间** 进行二分。每当二分到一个候选数 $x$ 时，只需统计数组中有多少元素小于或等于 $x$ ，就能判断 $x$ 是否满足第 $k$ 小值的要求。通过不断缩小搜索区间，最终即可锁定真实的中位数或第 $k$ 小值。

这种思路其实用到了[广义差分](https://xingguang641.com/posts/acm/acm-note/difference-idea/#差分的广义视角)的逻辑。直接定位中位数是一个极其严苛的 “点约束” ，要求数值在全局排序中精确对位，而二分答案则将这一硬性条件拆解为更宽松的 “范围统计” ，即计算 “小于等于 $x$ 的元素个数” 。这种 “以面求点” 的方式，本质上是将复杂的全局序关系简化为数值在值域区间上的贡献分布。通过判断计数值是否超过总数的一半，我们利用单调性不断逼近真相，将原本难以处理的静态单值查询转化为简单的计数查询。

在一些更复杂的题目中，仅仅统计 $\leq x$ 的数量还不够，往往还需要结合 **二值化（01 化）技巧** 。具体来说，可以将数组中的元素根据当前二分值 $x$ 进行转化，例如把满足条件的元素映射为 $1$ ，不满足的映射为 $-1$ 或 $0$ 。这样原本的 **中位数判定问题** 就可以转化为 **前缀和或子段和是否满足某种性质的问题** ，从而借助前缀和、树状数组或平衡树等数据结构高效完成统计。

> 具体的二值化处理中位数的技巧可以看这篇博客：[一种解决中位数问题的trick](https://www.cnblogs.com/dbywsc/p/19065445)

而在需要[动态维护中位数](https://xingguang641.com/posts/acm/acm-note/priority-queue/#数据流中位数问题)的场景中，通常会采用 **双优先队列** 的结构：用一个最大堆维护较小的一半元素，另一个最小堆维护较大的一半元素，并保持两边规模平衡。这样，每次插入新元素后，都能迅速得到当前的中位数。此外，[还有一类问题](https://xingguang641.com/posts/acm/acm-note/priority-queue/#最优状态维护问题)与优先队列密切相关：**需要输出前 k 个最优答案** 的题目。这类问题通常会维护一个优先队列来持续扩展当前最优状态，每次取出当前最小（或最大）的候选解，并生成新的候选结果。通过这种方式，可以按顺序得到前 $k$ 个答案，而无需枚举所有可能情况，大大降低时间复杂度。

### 离线型平均数问题

与中位数类似，**平均数最大化或最小化** 的问题也常常可以通过 **二分答案法** 来解决。设数组为 $A_1,A_2,\ldots,A_n$ ，如果题目要求在某种约束条件下找到 **最大平均值** ，通常并不会直接计算平均数，而是对答案 $x$ 进行二分。对于每一个候选值 $x$ ，我们只需要判断是否存在一个合法的选择方案，使得该方案的平均值 **不小于 x** 。

平均值问题的关键在于一个常见的代数变形。若某个集合 $S$ 的平均值满足：

$$
\frac{\sum_{i \in S} A_i}{|S|} \geq x
$$

则原式等价于：

$$
\sum_{i \in S} A_i - x|S| \geq 0
$$

进一步可以改写为：

$$
\sum_{i \in S} (A_i - x) \geq 0
$$

这样一来，只需要将原数组进行一次 **线性变换**：

$$
B_i = A_i - x
$$

原问题就转化为 **是否存在一个合法集合 S，使得数组累加和大于 0** 。此时问题已经不再涉及平均值，而变成了一个 **最大子段和或最大权值选择问题** ，通常可以通过动态规划、前缀和或其他数据结构来判断。这一技巧在算法竞赛中非常常见，例如求 **最大平均子段、最大平均路径、最大平均权值集合** 等问题。通过将平均值转化为线性和的形式，可以有效避免直接处理分数带来的复杂性，从而使问题更容易用常见的数据结构和动态规划方法解决。

# 逆向分析求解问题

在算法竞赛的博弈中，许多题目如果沿着题意正向推导，往往会陷入复杂的逻辑泥潭或面临难以处理的动态约束。此时，**逆向求解** 便成了一种极为强效的破局思路。其核心逻辑在于：我们不再苦思冥想如何直接构造出那个最优解，而是先大胆假设一个候选答案 $x$ ，随后尝试判断这个 $x$ 是否能够满足题目给出的所有约束条件。

这种先猜后验的思想能够演变为经典的 **二分答案法** ，主要依赖两个前置特征。首先，题目通常带有极强的 **最值暗示信号** ，如 “最大” 、“最小” 、“至多” 或 “至少” 等字眼。当问题要求在某个范围内逼近临界点，而非单纯的路径搜索或方案计数时，逆向验证的价值才会凸显。其次，解空间必须具备严苛的 **单调性** 。随着候选答案 $x$ 的增减，满足条件的可能性必须呈现单向变化。例如，若设定上界为 $k$ 时方案可行，那么放宽至 $k+1$ 也必然可行。这种性质确保了我们可以通过不断调整限制，在对数时间内锁定判定函数从 $\text{False}$ 跃迁至 $\text{True}$ 的临界点。

通过这种逆向思考，我们将棘手的 **最优化问题** 降级为了简单的 **判定性问题** 。这种解题重心从 “如何构建最优解” 到 “验证边界行不行” 的策略转移，极大地简化了代码实现的复杂度。我们不再需要直接在复杂的约束中寻找通路，而是从答案范围出发，通过不断的逻辑校验来缩小搜索空间。这种处理高难度约束优化题的策略，是竞赛中将复杂问题降维打击、化繁为简的核心套路。

## 可安排的任务数

## 题目要点解析

首先思考一下这道题的简单版本：假设 $tasks$ 数组和 $works$ 数组都是有序的，并且不存在大力药丸。那我们就可以直接用 **双指针匹配** 的思路来解决：如果当前工人的力量能够完成当前任务，就让他做该任务，否则跳过这个工人。整个过程就是工人与任务 **按顺序逐一配对** 。

在重新加入大力药丸之后，我们很容易会想到继续沿用上面的双指针策略：如果一个工人可以做当前的的任务，我们就让这个工人做当前的任务；如果不可以，我们就尝试让该工人吃药，再尝试完成当前的任务。这一思路看似合理，但其实是 **错误的** ，原因在于：当工人吃药之后，他在全体工人中的相对排序也随之改变。既然实力变强，他理论上就应该去承担更高难度的任务，而不再适合停留在原本的任务位置。

为了解决这个问题，我们可以尝试一个更合理的贪心：当一个工人能够胜任多个任务时，让他去完成 **他能力范围内最困难的任务** 。这是因为困难的任务可供选择的工人本来就更少，因此应当优先分配。可以轻易证明这个策略比按顺序逐一配对的思路更优。这就是所谓的[解锁任务](https://xingguang641.com/posts/acm/acm-type/greedy-algorithm/#田忌赛马贪心问题)的思路：对于每个工人，我们把所有他能做的任务加入一个任务集合，并优先分配其中最难的任务。

据此我们又可以尝试如下策略：如果当前工人完全做不了任务，那就让他吃药，再尝试解锁任务；如果仍无法完成，则撤销药丸并继续尝试下一个工人。不过这条看似严谨的贪心策略依然是 **错误的**：如果工人的能力数组为 $[2,3,4]$ ，任务的难度数组为 $[3,8,9]$ ，药丸只有一个并且药效为 `+5` 点能力值。那么我们直接给第一个工人吃药就只能做一个任务，而给第三个工人吃药则可以做两个任务。也就是说，我们无法确定哪个工人一定得吃药。

但如果我们事先就知道要完成的任务数量 $ans$ 情况就会变得明确。根据自然智慧，我们选择难度最低的 $ans$ 个任务，选择能力最大的 $ans$ 个工人。由于我们一定要完成 $ans$ 个任务，也就是每个被选中的工人都必须完成一个任务。因此在某个工人不吃药就无任务可做的情况下，我们就必须让他吃药。这样一来，我们就解决了正向思路中 “究竟该不该给某个工人吃药” 这一难以判断的问题。

同样道理，这里的 “工人能否完成 $T$ 个任务” 的判断具有天然的 **单调性**：

* 要求的任务越多，条件越苛刻，自然更难达成
* 要求的任务越少，条件越轻松，自然容易满足

因此我们可以使用二分来解决这个问题，时间复杂度为 $O(n \log n)$ 。

### Problem Statement

沿街有一排连续的房屋。每间房屋内都藏有一定的现金。现在有一位小偷计划从这些房屋中窃取现金。由于相邻的房屋装有相互连通的防盗系统，所以小偷 **不会窃取相邻的房屋** 。小偷的 **窃取能力** 定义为他在窃取过程中能从单间房屋中窃取的 **最大金额** 。

给你一个整数数组 `nums` 表示每间房屋存放的现金金额。形式上，从左起第 `i` 间房屋中放有 `nums[i]` 美元。另给你一个整数 `k` ，表示窃贼将会窃取的 **最少** 房屋数。小偷总能窃取至少 `k` 间房屋。

返回小偷的 **最小** 窃取能力。

### Constraints

- $1 \leq n.length \leq 10^5$
- $0 \leq nums[i] \leq 10^9$
- $0 \leq k \leq (nums.length + 1) / 2$

输入包含两行：

- 第一行包含两个整数 $n$ 和 $k$ 。
- 第二行包含 $n$ 个整数，表示数组的元素。

> $n \quad k$
>
> $nums_1 \quad nums_2 \quad \ldots \quad nums_n$

### Output

输出一个整数表示答案。
