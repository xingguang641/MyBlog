# 基础枚举技巧论

在算法实现中，**枚举是极为常见且基础的一类操作** 。无论是遍历状态空间、构造候选方案，还是对中间结果进行验证，枚举都承担着将抽象问题转化为具体计算过程的作用。由于其形式直接、逻辑清晰，枚举往往是解题过程中最早被采用的手段之一，也常常作为更复杂算法的出发点或验证手段。**在许多问题中，即便最终解法并非暴力枚举，枚举仍然在思路推导与结构分析阶段发挥着重要作用** 。

然而，枚举的实现方式并非只有简单的多重循环这一种选择。通过合理的 **状态表示、遍历顺序以及构造方式** ，可以使枚举过程更贴合问题的结构特征，从而在表达上更加简洁、逻辑上更加清晰。这类技巧主要关注的是 **枚举过程的组织方式本身** ，虽然不一定改变问题的规模或复杂度，但往往能够降低实现难度，并为后续的推导与改写提供更稳定的基础。

## 子集的枚举技巧

在算法竞赛中，**子集枚举** 是解决诸多问题的基础。对于一个含有 $n$ 个元素的集合，其子集的总数为 $2^n$ 。当 $n$ 的规模较小时，通过遍历所有可能的组合来寻找最优解或统计合法方案是一种极具通用性的策略。高效且正确地写出子集枚举逻辑，是深入学习状态压缩动态规划等进阶算法的先决条件。

最直观的子集枚举方式，是按照元素顺序，对每一个元素依次做 “选或不选” 的决策。这种思路与人类思考子集的方式完全一致，其自然实现形式就是深度优先搜索。设集合大小为 $n$ ，我们从第 $0$ 个元素开始处理，在递归的第 $i$ 层决定元素 $a_i$ 是否被加入当前子集。当所有元素都被处理完时，就得到了一个完整子集。整个搜索树是一棵深度为 $n$ 的二叉树，总共包含 $2^n$ 个叶子节点。

```cpp
vector<int> a;    // 原集合
vector<int> cur;  // 当前子集
int n;

void dfs(int i) {
    if (i == n) {
        // 此时 cur 就是一个子集
        // 在这里处理 cur
        return;
    }

    // 不选 a[i]
    dfs(i + 1);

    // 选 a[i]
    cur.push_back(a[i]);
    dfs(i + 1);
    cur.pop_back();
}
```

这种 DFS 枚举方式的特点在于结构非常清晰，递归层数与元素个数一一对应，并且在枚举过程中可以自然地加入剪枝条件或提前返回逻辑。因此，当题目需要在枚举过程中动态维护信息、或根据部分选择判断可行性时，这种写法往往最容易控制和修改。

另一种同样基础的非迭代方法是 **使用二进制掩码枚举子集** 。其核心思想是用一个整数的二进制表示来刻画子集状态：第 $i$ 位为 `1` 表示选择第 $i$ 个元素，为 `0` 表示不选择。这样，从 `0` 到 `(1<<n)-1` 的所有整数，恰好一一对应集合的所有子集。对每一个状态，只需检查每一位是否为 `1` 即可还原当前子集包含哪些元素。

```cpp
vector<int> a;
int n;

for (int mask = 0; mask < (1 << n); mask++) {
    vector<int> subset;
    for (int i = 0; i < n; i++) {
        if (mask & (1 << i)) {
            subset.push_back(a[i]);
        }
    }
    // subset 即为当前子集
}
```

这种枚举方式的优势在于状态表示极为紧凑，判断元素是否被选只需一次位运算，并且非常适合与状态压缩动态规划等算法结合使用。从本质上看，它与 DFS 枚举并没有任何区别，只是将 “选或不选” 的递归决策过程，直接编码进了二进制表示中。

在位掩码表示的基础上，存在一种在 **状态压缩动态规划** 中极为关键且高频使用的技巧：**在给定一个特定集合 $S$ 的前提下，枚举它的所有子集** 。在处理如子集 DP 或需要遍历 “某个状态的所有子状态” 的场景时，我们并不需要从 $0$ 盲目枚举到 $2^n-1$ ，而是仅需聚焦于那些满足 “属于 $S$ 的子集” 的状态。为了追求极致的执行效率，通常采用如下经典循环结构：

```cpp
for (int j = S; j; j = (j - 1) & S) {
    // j 是 S 的一个非空子集，在这里执行逻辑
}
```

这段简洁的代码能够 **不重不漏** 地按照递减顺序枚举出 $S$ 的所有非空子集。其核心原理在于利用了二进制减法的特性：当我们对当前子集 $j$ 执行 `j - 1` 操作时，会将 $j$ 最右侧的 `1` 变为 `0` ，并将其右侧所有的位翻转为 `1` ；随后通过与原集合 $S$ 进行 **按位与** 运算，系统会自动抹除掉不属于 $S$ 的多余位。这一过程精准地锁定了在数值上 **严格小于 $j$ 且仍属于 $S$ 子集** 的最大整数，从而实现了对子集空间的高效遍历。

这种写法在解决划分型动态规划等高级算法问题时具有无可替代的地位。相比于先枚举所有掩码再进行逻辑判断的朴素做法，该技巧通过直接操作二进制位，将总的时间复杂度优化至 $O(3^n)$ ，远优于 $O(4^n)$ 的常规实现。该算法从位运算的底层逻辑出发，通过消除无效状态的冗余迭代，使代码逻辑与集合论的数学结构达成了深度契合。

## 排列的枚举技巧

在排列问题中，枚举的核心不再是选择，而是 **在不重复使用元素的前提下，确定每一个位置放什么** 。因此，最自然的建模方式是：把排列看成一个长度为 $n$ 的序列，枚举第 $0$ 位、第 $1$ 位直到第 $n-1$ 位依次放入的元素。这种视角下，排列枚举几乎可以直接套用 DFS 的框架。

最基础的做法是 **DFS 按位置填数** 。递归深度表示当前已经确定了多少个位置，在第 `pos` 层，从所有 “尚未使用过” 的元素中任选一个放到当前位置即可。为了保证每个元素只使用一次，通常会维护一个 `used` 数组，用来标记哪些元素已经被选过。递归到深度为 $n$ 时，当前序列就是一个完整排列。

```cpp
vector<int> a;      // 原始元素
vector<int> perm;   // 当前构造中的排列
vector<bool> used;
int n;

void dfs(int pos) {
    if (pos == n) {
        // perm 是一个完整排列
        return;
    }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = true;
        perm.push_back(a[i]);
        dfs(pos + 1);
        perm.pop_back();
        used[i] = false;
    }
}
```

这种基于位置填充的递归模式，在逻辑上直接映射了排列定义的构造过程。这种写法的核心优势在于其具备极高的扩展性：由于每一层递归都明确对应序列中的一个具体位置，可以在枚举过程中直接注入约束条件或维护动态信息，例如在当前层执行剪枝以跳过不符合要求的搜索分支。代价是需要显式维护使用状态，代码略显冗长。

如果换一个角度看待排列，其实也可以认为排列就是对数组进行一系列交换的结果。基于这种理解，可以得到 **原地交换枚举排列** 的写法。具体思路是在递归的第 `pos` 层，决定哪个元素最终放在位置 `pos` ，于是从区间 `[pos, n)` 中任选一个元素，与 `a[pos]` 交换，然后递归处理下一位。回溯时再交换回来，保证数组状态不被破坏。

```cpp
vector<int> a;
int n;

void dfs(int pos) {
    if (pos == n) {
        // 当前 a 即为一个排列
        return;
    }
    for (int i = pos; i < n; i++) {
        swap(a[pos], a[i]);
        dfs(pos + 1);
        swap(a[pos], a[i]);
    }
}
```

这种交换式的构造逻辑，实质上是将待处理的数组划分为 “已确定” 和 “待选择” 两个动态区间。在每一层递归中，算法通过将后端的一个候选元素交换至当前索引位，隐式地完成了元素的选择与去重，从而避免了维护额外布尔数组的空间开销。从逻辑上看，该方法与显式使用 `used` 数组的 DFS 具有对称性：前者通过全局标记锁定可用元素，而此处则通过原地交换改变搜索空间，将所有状态演化直接体现在数组本身的排列组合中。

除了基于 DFS 的构造型枚举，还有一类非常常用的方式是 **直接按字典序枚举排列** 。这种方法并不关心排列是如何构造出来的，而是把排列本身当作一个状态，通过确定的规则在状态之间跳转。只要从字典序最小的排列开始，不断生成下一个排列，就可以在不重复、不遗漏的情况下遍历全部结果。在 C++ 中，这一过程由 `next_permutation` 封装完成。只要先对数组排序，然后反复调用该函数即可。

```cpp
sort(a.begin(), a.end());
do {
    // 当前 a 是一个排列
} while (next_permutation(a.begin(), a.end()));
```

理解 `next_permutation` 的核心在于：该算法并非任意构造一个新的排列，而是 **在全体排列的字典序序列中，严格生成当前排列的直接后继** 。为实现这一目标，算法对排列结构进行了精确分析，并通过一组确定性的操作，在保证字典序连续性的同时完成状态转移。其具体过程可以分解为以下三个步骤。

* **从右向左确定首个上升点**：从序列末尾向左扫描，找到第一个满足 $a[i] < a[i+1]$ 的位置 $i$ 。该位置的存在表明：区间 `[i+1, n)` 已经处于在固定前缀 `a[0..i]` 条件下的最大排列状态，若要获得字典序更大的排列，唯一可能的修改位置只能位于 $i$ 及其左侧。若不存在这样的 $i$ ，则说明整个序列为非递增序列。

* **在后缀中选择最小的可替换元素交换**：在区间 `[i+1, n)` 中，从右向左查找第一个满足 $a[j] > a[i]$ 的位置 $j$ ，并交换 `a[i]` 与 `a[j]` 。这一操作的作用在于：在第 $i$ 位对排列进行 **最小幅度的增大** ，从而保证新排列严格大于原排列，同时又尽可能接近原排列的字典序位置。

* **将后缀重排为字典序最小形式**：交换完成后，区间 `[i+1, n)` 仍保持非递增状态。为了使整体排列在所有可能的后继中达到字典序最小，只需将该区间反转，使其变为递增序列。此操作确保后缀部分在当前前缀固定的条件下取到最小可能值。

正是由于上述三步分别在 **修改位置的选择、增量大小的控制以及后缀排列的最小化** 三个层面进行了严格约束，`next_permutation` 才能够在不依赖递归或额外状态记录的前提下，按照字典序序完整无重复地遍历所有排列。

# 贡献法优化枚举

在算法设计中，许多问题表面上需要对大量子集或区间进行穷举，但直接枚举往往会产生极高的计算开销。尤其是在涉及 **组合计数** 或 **序列特征** 的复杂问题中，由于不同对象之间存在大量的重叠部分，简单的遍历会导致算法的时间复杂度随着数据规模呈指数级或高阶多项式级增长。如何在确保结果准确的前提下，通过转变观察维度来消除 **冗余的计算过程** ，是算法优化领域的核心课题之一。

**贡献法** 正是应对此类挑战的一种核心思想。其底层逻辑在于逆转对 “答案构成” 的观察视角：不再从宏观层面去逐一处理每一个复杂的整体组合，而是转而统计 **单个元素** 、**特定操作** 或 **局部结构** 在所有合法情形中对最终结果所产生的独立影响。通过这种 **化整为零** 的策略，全局的加和问题被转化为对各局部元素出现次数的计数问题，从而使许多高阶复杂度的算法能够在更优的时间内得出结论。

## 局部变化贡献法

局部变化贡献法适用于这样一类典型场景：**整体答案由多个局部成分累加而成，且单次操作仅影响其中极小比例的组成部分** 。在这类问题中，尽管最终输出是一个全局性的统计量，但其数值的波动往往源于某次操作所引发的 **局部状态位移** ，而非整体结构的重构。因此，实时维护答案的关键在于精确捕捉并修正那些因操作而产生的 **增量贡献** 。

其核心思想在于建立一种 **差分视角** ，即通过分析单次修改相对于原状态所引入的净变化，来规避对不变部分的重复扫描。与其在每次操作后盲目地重新推导整个答案，不如直接刻画 “这次修改到底改变了什么” 。只要能够精确界定这一变化对最终结果的影响范围，便可以在不触及海量冗余数据的前提下，实现对全局状态的同步更新。

以维护数组 $a[1..n]$ 的元素总和为例，若面临频繁的单点修改与求和查询，传统的遍历方案会产生 $O(n)$ 的线性开销，在数据规模较大时效率极低。然而，通过 **贡献度拆解** 可以发现，位置 $i$ 的数值由 $a[i]$ 变更为 $x$ 时，数组中其余 $n-1$ 个元素对总和的贡献完全恒定。这意味着全局答案的演变仅取决于该特定位置的 **新旧值差异** 。

基于此观察，算法仅需维护一个全局变量 `sum`。当修改发生时，通过计算 `x - a[i]` 这一局部变化量并将其累加至 `sum`，即可在 $O(1)$ 时间内完成状态转移。这种从 “重新计算答案” 向 “修正局部偏差” 的逻辑转变，本质上是利用了操作的 **局部性特征** 来消除计算冗余，使得算法在处理高频动态更新任务时，展现出极高的执行效率与工程稳定性。

## 最小值之和查询

[题目链接](https://atcoder.jp/contests/abc420/tasks/abc420_c)

### Problem Statement

给定两个长度为 $N$ 的整数序列

$$
A = (A_1, A_2, \ldots, A_N) \quad B = (B_1, B_2, \ldots, B_N)
$$

以及一个整数 $Q$ 表示查询数量。每个查询会描述如下操作：

* 输入一个字符 $c_i$ 和两个整数 $X_i, V_i$：

  * 若 $c_i =$ `"A"` ，则将 $A_{X_i}$ 修改为 $V_i$
  * 若 $c_i =$ `"B"` ，则将 $B_{X_i}$ 修改为 $V_i$

在执行完该修改之后，计算并输出：

$$
\sum_{k=1}^N \min(A_k, B_k)
$$

即序列 $A$ 与序列 $B$ 的对应元素最小值之和。

### Constraints

* $1 \leq N, Q \leq 2 \times 10^5$
* $1 \leq A_i, B_i \leq 10^9$
* $c_i$ 只能是字符 `"A"` 或 `"B"`
* $1 \leq X_i \leq N$
* $1 \leq V_i \leq 10^9$
* 所有输入均为整数

### Input

输入包含多行数据，格式如下：

- 第一行包含两个整数 $N$ 和 $Q$ 。
- 第二行包含 $N$ 个整数，表示序列 $A$ 。
- 第三行包含 $N$ 个整数，表示序列 $B$ 。
- 接下来的 $Q$ 行中，每行表示一次查询，包括一个字符与两个整数。

> $N \quad Q$
>
> $A_1 \quad A_2 \quad \ldots A_N$
>
> $B_1 \quad B_2 \quad \ldots B_N$
>
> $c_1 \quad X_1 \quad V_1$
>
> $c_2 \quad X_2 \quad V_2$
>
> $\ldots$
>
> $c_Q \quad X_Q \quad V_Q$

### Output

输出 $Q$ 行，每行对应一个查询的结果，即执行修改并计算最小值之和后的输出。

### Sample Input 1

```txt showLineNumbers=false
4 3
3 1 4 1
2 7 1 8
A 2 3
B 3 3
A 1 7
```

### Sample Output 1

```txt showLineNumbers=false

9
9
```

### Sample Input 2

```txt showLineNumbers=false
1 3
1
1000000000
A 1 1
A 1 1
A 1 1
```

### Sample Output 2

```txt showLineNumbers=false
1
1
1
```

### Sample Input 3

```txt showLineNumbers=false
5 3

100 100 100 100 100

```

### Sample Output 3

```txt showLineNumbers=false

```

## 滑动窗口最大值

$$

$$

## 对象交换贡献法

对象交换贡献法适用于答案由大量组合对象或子结构累加而成的情境。其核心逻辑在于 **逆向重构问题维度**：我们不再机械地枚举所有可能的整体组合（如所有子数组、所有路径），而是转而分析每一个独立元素、每一条边或每一个数值在最终结果中的 **具体占位与贡献频次** 。这种从 “全局搜索” 向 “局部统计” 的视角切换，能够从逻辑底层消除冗余计算，大幅压缩算法的执行时间。

以 “计算数组所有子数组最小值之和” 这一经典问题为例，若采取直观的区间枚举策略，时间复杂度将达到 $O(n^2)$ 甚至更高，其低效的本质在于对同一元素的最小值属性进行了大量重复判定。若变换视角，可以发现每个元素 $a[i]$ 仅在特定的区间范围内充当最小值。通过利用单调栈等工具预处理出每个元素作为最小值的 **左右边界** ，即可精确计算出该元素对总和的贡献次数，从而将复杂度优化至 $O(n)$ 。

这种 **按位统计贡献** 的思想在多类数据结构问题中具有普适性。在树形结构中，求取所有路径权值之和时，可以从 **边的维度** 切入，统计每条边在所有路径组合中出现的次数，将其与边权相乘后累加；在几何计算中，求解点对间的曼哈顿距离和时，可将横纵坐标解耦，单独统计坐标点在各维度上的线性贡献；在数论领域，求取 $1$ 到 $n$ 所有整数的因子个数总和，亦可转化为统计每个数作为因子在给定范围内的出现频率。

归结而言，对象交换贡献法的精髓在于 **由元素属性倒推全局答案** ，而非由答案定义去契合元素。无论是处理静态的组合计数，还是动态的序列特征，其核心步骤均在于明确单个对象对最终评价指标的映射关系，并将这些影响量化后进行线性加权。这种方法不仅显著提升了计算效率，更使复杂的逻辑结构变得层次分明，是处理高阶枚举类问题时不可或缺的 **分析范式** 。

# 预处理优化枚举

在算法设计中，尤其是面对涉及高频查询的场景，若每次请求都从头执行完整的枚举或扫描，往往会导致不可接受的时间开销。因此，一种核心的优化思路是：**通过预处理机制将计算压力前移，提前处理与具体查询参数无关的公共部分** 。其本质在于将重复性劳动转化为一次性投入，通过适度的空间开销或初始时间成本，换取查询阶段的极速响应。这种 **时空权衡** 的策略，是提升大规模数据处理性能的关键。

预处理之所以高效，是因为在动态的查询流中，往往存在大量 **静态不变的底层数据** ，如原始数组、图拓扑结构或固定的约束条件。这些基础信息在所有查询开启前便已定型，不随单次输入而波动。通过对这些固有属性进行预先的逻辑建模，我们可以构建出高效的辅助结构（例如前缀和数组、哈希表或单调栈），从而在查询发生时直接调取预存的中间状态，规避冗余的遍历过程。

在具体的工程实现中，预处理通常将复杂的逻辑推导简化为 **查表或快速状态合并** 的操作模式。例如，借助前缀和技术可将区间求和的复杂度从 $O(n)$ 降低至 $O(1)$ ；利用 ST 表可以在常数时间内完成区间最值查询。更有甚者，预处理会配合树状数组或线段树等结构，在兼顾动态修改的同时维持查询的高效性。总之，预处理的精髓在于 **压缩查询路径并消除计算冗余** ，它是优化枚举过程、打破性能瓶颈最有效的手段之一。

## 题目要点解析

针对区间范围内查询某个点对或子区间是否存在，也就是 **区间查区间** 的问题，一种行之有效的策略是为每个可能的右端点 $r$ 寻找其对应的 **最优左端点 l** 。具体到括号序列或点对匹配场景，我们通过贪心原则找到距离 $r$ 最近且能与其满足约束条件的 $l$ ，这种选择不仅能够大幅收缩搜索空间，还能为后续的去重提供天然的逻辑支持。在预处理阶段，我们通过这种映射关系构建出一个 **左端点数组 L** ，其中 $L[i]$ 记录了以 $i$ 为右端点时，合法结构所能达到的最大左边界下标。由此，判断一个给定区间 $[l, r]$ 是否包含合法结构的准则便可以转化为：

$$
\max(L_l, \ldots, L_r) \geq l
$$

这一公式说明了只要区间内存在至少一个右端点，其对应的 **最佳左端点并未越过询问区间的左边界** ，则该区间判定为有效。进一步观察可以发现，由于在逻辑构造上每个位置 $i$ 的最优左端点 $L[i]$ 必然满足 $L[i] \leq i$ ，这意味着对于任何 $k < l$ 的位置，其 $L[k]$ 必然也小于 $l$ ，对最终判定的贡献为负。这一关键性质允许我们将区间最值查询进一步简化，即上述公式等价于：

$$
\max(L_l, \ldots, L_r) = \max(L_0, L_1, \ldots, L_r) \geq l
$$

通过这一步转化，原本需要使用线段树或 RMQ 维护的区间最值问题，被成功降维成了简单的 **动态规划前缀最大值** 问题。在实际实现中，我们仅需在线性时间内预处理出 **前缀最大值数组** ，即可在 $O(1)$ 的时间内响应任何关于区间合法性的存在性询问。

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const int MAX = 2e5 + 7;
const int VAL = 1 << 20;
int n, q, x;
int a[MAX], L[MAX];
int preMax[MAX];
int lastPos[VAL];

int main() {
    cin >> n >> q >> x;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    memset(lastPos, 0, sizeof(lastPos));
    for (int i = 1; i <= n; i++) {
        int target = a[i] ^ x;
        L[i] = lastPos[target]; 
        
        lastPos[a[i]] = i;
    }

    preMax[0] = 0;
    for (int i = 1; i <= n; i++) {
        preMax[i] = max(preMax[i - 1], L[i]);
    }

    for (int i = 0; i < q; i++) {
        int l, r;
        cin >> l >> r;
        if (preMax[r] >= l) {
            cout << "yes" << endl;
        } else {
            cout << "no" << endl;
        }
    }
}
```

## 题目要点解析

本题的核心挑战在于处理极大量的询问 $Q = 5 \times 10^5$ ，这使得常规的 $O(N)$ 模拟无法在时限内完成。解题的关键突破口在于挖掘题目给出的参数限制：由于礼物的价值 $P_i$ 、情绪增加量 $A_i$ 和减少量 $B_i$ 均不超过 $500$ ，高桥君的情绪值在变化过程中表现出明显的收敛特性。当初始情绪值 $X$ 远大于 $500$ 时，他会因为 “眼光过高” 而对收到的礼物持续感到失望，导致情绪值呈线性下降趋势。这种下降会一直持续，直到情绪值跌入特定的波动区间。

我们可以定义一个临界值 $M = 1000$ 。只要当前情绪值高于这个临界值，由于 $P_i \leq 500$ 的限制，高桥君必然会触发 “情绪减少 $B_i$ ” 的逻辑。只有当情绪值降低到 $1000$ 以下时，才可能因为 $X \leq P_i$ 而触发 “情绪增加 $A_i$ ” 的逻辑。这里有一个非常重要的性质：情绪值一旦进入 $[0, 1000]$ 区间，就永远不会再超过 $1000$ 。这是因为触发增加逻辑的前提是 $j \leq P_i \leq 500$ ，即便加上最大的增加量 $A_i \leq 500$ ，结果也恰好维持在 $1000$ 。基于这一观察，我们可以将整个过程划分为 “高位线性下降” 和 “低位区间死循环” 两个阶段。

针对低位区间的变动，我们利用动态规划进行预处理。设 $dp[i][j]$ 表示在处理第 $i$ 个礼物前，若当前情绪值为 $j$（其中 $0 \leq j \leq 1000$ ），在处理完剩余所有礼物后最终的情绪值。我们可以通过逆向推导来填充这个表：从最后一个礼物 $N$ 开始往前考虑，根据当前礼物 $i$ 的参数计算出处理完该礼物后的新情绪值 $j'$ 。

$$
j' = \begin{cases} j + A_i & \text{if } j \leq P_i \\ \max(0, j - B_i) & \text{if } j > P_i \end{cases}
$$

由于上述性质保证了 $j' \leq 1000$ ，状态转移可以简单地写为：

$$
dp[i][j] = dp[i+1][j']
$$

对于每个具体的询问 $X_i$ ，我们利用预处理的 $B_i$ 前缀和 $sumB[k] = \sum_{j=1}^k B_j$ 进行加速。通过二分查找快速定位最小的下标 $k$ ，使得：

$$
X_i - sumB[k] \leq 1000
$$

若在处理完所有礼物前找到了这个 $k$ ，则说明情绪值在第 $k$ 个礼物处跌入了预处理区间。此时，该询问的最终答案直接由 $dp[k+1][\max(0, X_i - sumB[k])]$ 给出。如果直到最后礼物领完，情绪值依然高于 $1000$ ，答案则是 $X_i - sumB[N]$ 。这种方法将查询复杂度降至 $O(\log N)$ ，能够完美解决大规模询问下的时限挑战。

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
int N, Q;
int dp[10005][1005];
int P[10005], A[10005], B[10005];
long long preB[10005];

int main() {
    cin >> N;
    for (int i = 0; i < N; i++) {
        cin >> P[i] >> A[i] >> B[i];
        preB[i + 1] = preB[i] + B[i];
    }

    // 逆向 DP 预处理
    for (int j = 0; j <= 1000; j++) {
        dp[N][j] = j;
    }
    for (int i = N - 1; i >= 0; i--) {
        for (int j = 0; j <= 1000; j++) {
            int next_j;
            if (P[i] >= j) {
                next_j = j + A[i];
            } else {
                next_j = max(0, j - B[i]);
            }
            dp[i][j] = dp[i + 1][next_j];
        }
    }

    cin >> Q;
    while (Q--) {
        ll x; cin >> x;
        int k = lower_bound(preB, preB + N + 1, x - 1000) - preB;
        
        if (k > N) {
            cout << x - preB[N] << endl;
        } else {
            ll val = max(0LL, x - preB[k]);
            cout << dp[k][(int)val] << endl;
        }
    }
}
```

# 随机化优化枚举

在一些题目中，如果完全按照确定性的思路去设计算法，往往需要维护复杂的数据结构、进行繁琐的分类讨论，或者推导较为困难的性质。这类题目虽然通常存在严格的确定性解法，但实现难度较高。在这种情况下，可以考虑引入 **随机化** 作为一种简化思路的手段。需要注意的是，随机化一般并不是首选方法，而更多是在 **常规做法较难实现时的一种工程上的折中策略** 。

随机化方法的核心思想在于：如果题目中的关键结构在整体候选空间中 **并不是极其稀少** ，那么通过随机选择或随机顺序处理，就有较高概率接触到这些关键结构，从而避免对所有情况进行系统性的完整枚举。只要重复尝试的次数足够多，算法就能够在概率意义上获得正确答案，同时实现复杂度也往往明显低于复杂的确定性方案。

### 1. 随机排序（Random Shuffle）

有些算法在最坏情况下复杂度较高，但在平均情况下性能很好，而输入数据的顺序可能会触发最坏情况。在这种情况下，可以先对数据进行 **随机打乱** ，再执行原本的算法，使得算法在期望意义下保持较好的复杂度表现。

这种思想在许多经典算法中都有体现，例如 **随机化快速排序** 和 **快速选择算法** 。通过随机选择枢轴或随机打乱数据，可以有效避免某些特殊输入导致的退化情况，使算法整体表现更加稳定。

### 2. 随机抽样（Random Sampling）

在某些问题中，答案往往由少量关键元素决定，而这些元素在整体数据中所占比例并不低。这时可以通过 **随机抽样** 的方式选取若干候选对象，再对这些对象进行验证。如果抽样次数足够多，就有很大概率命中与答案相关的关键结构。

这种方法在一些 **图论问题、几何问题以及关系判定问题** 中较为常见。例如可以随机选取若干点、若干边或若干元素作为候选结构，再通过判定过程验证其是否满足题目要求。相比系统性地遍历所有可能情况，随机抽样往往能以更低的代价接触到关键解。

### 3. 随机哈希（Random Hashing）

在一些需要比较复杂结构的问题中，可以为元素赋予 **随机权值** ，从而将结构信息映射为简单的数值形式进行比较。这种方法通常被称为 **随机哈希** 。

通过随机赋值，可以把复杂结构压缩为整数或哈希值，再通过数值运算进行快速判断。例如在一些集合比较、子结构判定或结构等价判断的问题中，可以利用随机哈希来大幅简化实现过程。虽然理论上存在哈希冲突的可能，但通过选择足够大的随机范围，冲突概率通常可以控制在极低水平。

### 4. 随机验证（Random Verification）

另一类常见的随机化技巧是 **概率验证** 。在这种方法中，并不一定直接构造答案，而是通过随机生成若干测试或随机选择若干样本来验证某个性质是否成立。只要验证次数足够多，就能够在概率意义上保证结果的可靠性。

这种方法通常属于 **Monte Carlo 算法** 的范畴：算法运行速度较快，但允许极小概率出现错误。在竞赛环境中，只要错误概率能够控制在足够小的范围内，这种方法通常是可以接受的，并且能够显著降低实现复杂度。

## 题目要点解析

这道题要求判断是否存在一条直线，使得它 **经过严格超过一半的点** 。由于一条直线只需要 **两个点** 就可以唯一确定，因此最直接的思路是枚举所有点对，通过两点确定直线，再统计有多少点落在这条直线上。但如果直接枚举所有点对，复杂度为 $O(N^2)$ ，在 $N \le 5 \times 10^5$ 的条件下显然无法接受，因此需要寻找更高效的方法。

关键在于题目的一个重要性质：如果存在满足条件的直线，那么这条直线至少经过 **超过一半的点**。设这样的点集大小为 $M$ ，则：

$$
M > \frac{N}{2}
$$

因此如果我们 **随机选择两个点** ，它们同时落在这条直线上的概率其实是相当高的。更具体地说，随机选择两个点同时来自这 $M$ 个共线点的概率为：

$$
\left(\frac{M}{N}\right)^2
$$

而由于 $M > N/2$ ，这个概率至少为：

$$
\left(\frac{1}{2}\right)^2 = \frac{1}{4}
$$

这意味着只要进行若干次随机抽样，就有很高概率能够抽到 **同一直线上的两个点**。因此可以采用 **随机化算法** 来解决问题。由于每次随机尝试的成功概率至少为 $1/4$ ，因此只需要进行几十次随机抽样即可将失败概率降到极低。每次验证需要遍历全部点，复杂度为 $O(N)$ ，因此整体复杂度约为 $O(TN)$ ，其中 $T$ 为随机尝试次数。
