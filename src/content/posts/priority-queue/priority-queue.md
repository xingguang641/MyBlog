# 优先队列的基本结构

**优先队列（Priority Queue）** 是一种特殊的队列结构。与普通队列严格遵循 “先进先出（FIFO）” 规则不同，优先队列并不关心元素进入队列的先后顺序，而是根据元素所具有的 **优先级** 来决定其出队次序。优先级高（或低，取决于具体定义）的元素将被优先取出，这使得优先队列在许多需要动态维护 “最优元素” 的场景中具有重要作用。

在实际应用中，优先队列几乎总是通过 **堆（Heap）** 来实现，其中最常见的实现形式是 **二叉堆** 。堆在逻辑结构上是一棵二叉树，但并非任意形态的二叉树，而是一棵满足特定结构约束的 **完全二叉树** 。在此结构基础之上，堆还进一步满足堆序性质，从而保证队首元素始终是当前优先级最高（或最低）的元素。

## 完全二叉树

**完全二叉树（Complete Binary Tree）** 是二叉树这一类基本树结构中的一种重要类型，它并不关注节点中存储的数据内容或节点之间的逻辑大小关系，而是重点规范二叉树在层次结构和节点排列顺序上的整体形态。正是这种对结构的严格限制，使得完全二叉树在节点数量一定的情况下能够保持较小的高度，并具备良好的顺序存储特性。围绕这一结构特征，其定义如下：

> 若一棵二叉树中，除最底层外，其余各层的节点均被完全填满，并且最底层的节点按照从左到右的顺序连续排列，则称该二叉树为完全二叉树。

这一结构约束保证了二叉树的节点分布尽可能紧凑，使得在给定节点数量的情况下，树的高度保持在较小的范围内。也正因为这一特性，完全二叉树非常适合用 **数组** 的形式进行存储，而无需借助额外的指针结构，这为堆的高效实现提供了重要基础。

![优先队列图像](src\content\posts\priority-queue\优先队列1.jpg)

![优先队列图像](src\content\posts\priority-queue\优先队列2.jpg)

通过上述示意图可以直观地看出，完全二叉树中的节点是按照 **层序遍历** 的顺序逐层填充的：从根节点开始，自上而下、从左到右依次放置节点。尤其是在最底层中，节点必须严格遵循从左到右连续排列的原则，不允许出现位置空缺而右侧仍然存在节点的情况，这一点是判断完全二叉树的重要特征之一。

需要特别注意的是，如果最底层的节点 **未按照从左到右的顺序连续排列** ，即使整棵树在除最底层之外的其他层级上看起来已经被完全填满，也不能被称为完全二叉树。如下图所示，最底层节点的排列出现了明显的 “跳空” 现象，破坏了节点的连续性，因此该结构并不满足完全二叉树的定义。

![优先队列图像](src\content\posts\priority-queue\优先队列3.jpg)

这一结构性的约束看似严格，却为后续堆的插入、删除等操作提供了天然的便利条件，使得优先队列能够在保证结构稳定的同时，高效地完成动态调整。

## 大根堆与小根堆

在优先队列的实现中，仅依赖完全二叉树所提供的结构约束，还不足以确定元素在出队时的先后顺序。完全二叉树只能保证节点在空间上的紧凑排列，却无法体现 “谁的优先级更高” 。为了保证每次都能够 **高效地** 取出当前优先级最高（或最低）的元素，堆结构还必须满足一种额外的约束条件，称为 **堆序性质（Heap Property）**。正是这一性质，使得堆能够在对数时间内完成插入与删除操作。根据堆序性质约束方向的不同，二叉堆通常可以分为 **大根堆** 和 **小根堆** 两种类型。

**大根堆（Max Heap）** 是指在一棵完全二叉树中，**任意一个节点的值都不小于其左右子节点的值** 。换言之，在大根堆中，每个父节点的优先级都高于或等于其子节点，这种关系会沿着树结构自上而下层层传递。由此可以直接得到一个非常重要的结论：在大根堆中，**堆顶元素始终是整棵堆中值最大的元素** 。正因为这一特性，大根堆非常适合用于需要频繁获取当前最大值的场景。

![优先队列图像](src\content\posts\priority-queue\优先队列4.jpg)

**小根堆（Min Heap）** 在结构上与大根堆完全一致，二者都基于完全二叉树进行组织，区别仅体现在堆序性质的方向上。在小根堆中，**任意一个节点的值都不大于其左右子节点的值** ，即父节点的优先级不低于其子节点，较小的元素会不断向上 “浮动” 。因此，同样可以得到一个对应的结论：在小根堆中，**堆顶元素始终是整棵堆中值最小的元素** 。这一性质使得小根堆非常适合用来实现优先队列、找最小值或进行排序等操作。

![优先队列图像](src\content\posts\priority-queue\优先队列5.jpg)

总体来看，大根堆与小根堆在逻辑上都可以看作是满足不同堆序性质的完全二叉树。前者关注最大值，后者关注最小值，二者共享相同的结构基础。在实际实现中，这种逻辑上的树结构并不会通过指针来表示，而是映射到数组这样的顺序结构中。接下来我们将从 **逻辑结构与物理结构** 的角度，说明完全二叉树与顺序存储之间的对应关系。

## 逻辑结构与物理结构

在数据结构中，**逻辑结构** 描述的是数据元素之间在概念层面上的组织关系，强调 “数据之间是什么关系” ，而 **物理结构** 则关注这些数据在内存中的实际存储方式，强调 “这些关系是如何被实现的” 。同一种逻辑结构，往往可以对应多种不同的物理实现方式。对于堆这种数据结构而言，其逻辑结构可以抽象为一棵满足堆序性质的 **完全二叉树** ，而在具体编程实现时，则通常选择使用 **顺序存储结构（数组）** 作为其物理结构。

之所以能够用数组来表示完全二叉树，关键原因在于完全二叉树本身具有非常强的结构约束：节点按照 “从上到下、从左到右” 的顺序连续排列，不存在中间空缺的情况。这种紧凑的排列方式，使得树中节点在逻辑上的父子关系，可以通过数组下标之间的数学关系来隐式表达，而无需显式维护指针或引用。数组中元素的存放顺序，恰好对应完全二叉树的 **层序遍历顺序** ，这为堆的高效实现提供了天然的便利。

![优先队列图像](src\content\posts\priority-queue\优先队列6.jpg)

在实际实现中，我们通常将完全二叉树的节点按照层序依次存入数组中。这样一来，虽然在逻辑上我们仍然把堆看作一棵树，但在物理层面上，它只是一段连续的内存空间。通过这种映射方式，树中节点之间的父子关系可以通过简单的下标计算直接确定，从而在保证结构正确性的同时避免了额外的指针开销，显著提升了存储及访问效率。

### 下标从 1 开始的对应规则

当数组下标从 1 开始时，完全二叉树中节点之间的对应关系如下：

* 若某节点存储在数组下标为 $i$ 的位置

  * 其左子节点的下标为 $2i$
  * 其右子节点的下标为 $2i + 1$
  * 其父节点的下标为 $\lfloor i / 2 \rfloor$

![优先队列图像](src\content\posts\priority-queue\优先队列7.jpg)

这种对应关系直接来源于完全二叉树节点在数组中的连续排列特性，使得父子节点在数组中的位置呈现出稳定而规律的倍数关系。借助这一规则，我们可以在不显式存储任何树形结构信息的前提下，仅通过下标运算就快速定位任意节点的父节点或子节点，这也是堆操作能够保持较低时间复杂度的重要原因之一。

### 下标从 0 开始的对应规则

在某些语言或标准库的实现中，数组下标可能从 0 开始，此时节点之间的对应关系会略有不同：

* 若某节点存储在数组下标为 $i$ 的位置

  * 其左子节点的下标为 $2i + 1$
  * 其右子节点的下标为 $2i + 2$
  * 其父节点的下标为 $\lfloor (i - 1) / 2 \rfloor$

虽然下标公式在形式上有所变化，但其本质仍然是相同的：都是充分利用完全二叉树节点排列紧凑、无空洞的结构特点，通过简单的算术运算来确定节点之间的父子关系。正是这种从逻辑结构到物理结构的高效映射，使得堆能够在数组上实现插入、删除和调整等核心操作，并成为优先队列最常用、也最实用的底层实现方式。

## 优先队列的基本原理

堆是一种在完全二叉树结构之上引入 **堆序性质** 的数据结构。完全二叉树为堆提供了紧凑而稳定的结构基础，而堆序性质则进一步约束了父节点与子节点之间的大小关系，使得堆顶元素始终能够表示当前的最优值（最大值或最小值）。需要注意的是，**堆序性质并不是天然成立的** 。当我们仅仅按照层序顺序，将一组元素依次放入数组中时，得到的结果往往只是一个 “形状正确” 的完全二叉树。此时节点之间的大小关系仍然是杂乱无序的，远未满足大根堆或小根堆的要求。换言之，结构上的正确，并不意味着它已经是一个合法的堆。

因此堆的核心问题并不在于 “如何存储元素” ，而在于 **如何在保持完全二叉树结构不变的前提下，通过一系列局部调整，使整棵树重新满足堆序性质** 。无论是向堆中插入新元素、删除堆顶元素，还是从一组无序数据中直接构造堆结构，其本质都可以归结为对堆序性质的不断修复与维护。基于这一认识，接下来需要重点讨论的就是：**在给定一个无序数组的情况下，如何高效地将其整体转化为一个合法的堆结构** 。这一过程通常被称为 **建堆（Heapify）**，也是理解堆实现机制的关键一步。

### 堆的创建

如前所述，一个无序数组在顺序存储下天然对应一棵 **完全二叉树** ，但这棵树通常并不满足堆序性质。建堆的目标是在 **保持节点相对位置不变**（即不破坏完全二叉树结构）的前提下，通过一系列局部调整，使整棵树满足大根堆或小根堆的要求。堆序性质仅涉及 **父节点与子节点之间的局部关系** ，因此，只要每个子树都满足堆序性质，整棵树自然就是一个合法的堆。

![建堆图像](src\content\posts\priority-queue\建堆1.jpg)

建堆通常采用 **自底向上（Bottom-Up）** 的方式进行。这是因为在完全二叉树中，所有叶子节点本身就是合法的堆——它们没有子节点，不可能违反堆序性质。因此，我们可以从 **最后一个非叶子节点** 开始，依次向上，对每个节点执行 **向下调整（Sift Down / Heapify Down）** 操作。

![建堆图像](src\content\posts\priority-queue\建堆2.jpg)

在向下调整过程中，我们关注的是当前节点与其子节点的局部关系。以大根堆为例，向下调整的目标是保证当前节点的值不小于其子节点的值。具体做法是先比较当前节点与左右子节点的大小，如果当前节点小于子节点中的最大值，就将其与该子节点交换，然后将焦点节点下移到子节点的位置，重复比较与交换，直到当前节点大于等于其子节点或到达叶子节点。

首先看第一个非叶子节点，即 5 号节点 60。它的左子节点是 53，而右子节点为空。在大根堆的要求下，父节点必须大于等于其子节点。由于 60 大于左子节点 53，并且右子节点为空，因此 60 节点与子节点之间并不存在违反堆序性质的情况。可以看出，以 60 为根的子树已经是一个合法的大根堆，无需进行调整。

![建堆图像](src\content\posts\priority-queue\建堆3.jpg)

4 号节点 48 同样满足堆序性质，无需调整。接下来是 3 号节点，它的左子节点是 7，右子节点是 51，而 3 号节点的值小于右子节点 51，因此需要进行交换调整。交换完成后，以 3 号节点为根的子树就形成了大根堆。

![建堆图像](src\content\posts\priority-queue\建堆4.jpg)

![建堆图像](src\content\posts\priority-queue\建堆5.jpg)

需要注意的是，**节点交换不仅要改变树的逻辑结构，还必须同步调整数组中的存储顺序** ，以保证物理存储与逻辑结构完全一致。每一次交换操作通过移动节点的值，实现对子树堆序性质的局部维护。通过这样的局部调整，以当前节点为根的子树就能重新满足堆序性质，无论是上滤还是下滤，都能确保父节点与子节点的大小关系正确，从而 **保证整个堆在逻辑和物理结构上都被正确维护** 。

![建堆图像](src\content\posts\priority-queue\建堆6.jpg)

![建堆图像](src\content\posts\priority-queue\建堆7.jpg)

再来看一个需要多次交换的例子，以 2 号节点 27 为例。27 节点的值小于左右子节点，其中最大值是右子节点 60，因此首先与右子节点交换。交换后，27 节点下移到 5 号位置，但此时它仍然小于左子节点 53，于是再次进行交换。经过这两次调整后，以 2 号节点为根的子树最终形成大根堆，父节点始终大于等于子节点，堆序性质得以完全恢复。

![建堆图像](src\content\posts\priority-queue\建堆8.jpg)

![建堆图像](src\content\posts\priority-queue\建堆9.jpg)

![建堆图像](src\content\posts\priority-queue\建堆10.jpg)

![建堆图像](src\content\posts\priority-queue\建堆11.jpg)

按照自底向上的顺序依次对每个非叶子节点进行调整后，整棵树最终形成一个完整的最大堆（大根堆）。此时，每个父节点的值都大于等于其子节点，堆序性质在整棵树中得到了严格维护。通过这种自底向上的建堆方式，局部的向下调整逐步修复了所有子树的堆序关系，使原本无序的数组被高效地组织成一棵合法的堆。这不仅保证了堆的正确性，也直观地展示了局部调整如何累积形成全局有序的效果。

![建堆图像](src\content\posts\priority-queue\建堆12.jpg)

通过这个过程，我们可以清楚地看到，每次向下调整都是对局部子树的堆序修复，而自底向上的策略确保最终整棵树都符合堆的定义。相比逐个插入构建堆的方法，自底向上的建堆更为高效，总时间复杂度为 $O(n)$ ，因此成为构造堆的标准且高效的方法。建堆的完整代码如下：

```c showLineNumbers
void heapify(vector<int>& arr, int n, int i) {
    int largest = i;          // 假设当前节点为最大
    int left = 2 * i + 1;     // 左子节点索引
    int right = 2 * i + 2;    // 右子节点索引

    if (left < n && arr[left] > arr[largest])
        largest = left;

    if (right < n && arr[right] > arr[largest])
        largest = right;

    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void buildMaxHeap(vector<int>& arr) {
    int n = arr.size();
    for (int i = n / 2 - 1; i >= 0; --i) {
        heapify(arr, n, i);
    }
}
```
