# 归并排序基本原理

1945 年，约翰·冯·诺依曼（John von Neumann）首次提出了归并排序（Merge Sort）算法。作为分治（Divide and Conquer）思想在排序问题上的经典应用，它在算法理论和实际工程中都具有重要意义。归并排序的核心理念可以概括为 “分而治之，治而合之” 。在排序过程中，算法首先不断将原始序列拆解为更小的子序列，直到每个子序列只包含一个元素为止。由于单个元素本身就具有天然有序性，这一步实际上完成了所有局部子问题的最小化。

当拆分过程结束后，算法便进入归并阶段。在这一阶段中，程序会自递归的底部开始，将已经有序的子序列两两合并，并在合并时通过比较操作保证结果依旧有序。随着合并任务逐层向上推进，多个局部有序解逐渐汇聚为一个完整的全局有序序列，从而完成整个排序过程。得益于这一严谨且结构化的流程，归并排序能够保证排序稳定性，即相同元素的相对顺序不会发生改变。同时，它也非常适合用于外部排序场景，如处理数据量巨大到无法一次性加载进内存的任务。因此，归并排序不仅是理解分治思想的最佳范例之一，也是现代高效排序算法的重要理论基础。

## 算法图解

假设我们有一个初始数列 $[8, 4, 5, 7, 1, 3, 6, 2]$ 。下面让我们沿着归并排序的执行流程，完整感受它如何一步一步将无序变为有序。

### 递归拆分阶段

归并排序首先会从整体入手，将序列逐步对半拆分，就像不断把问题往更小的局部压缩。这个拆分过程呈现出一棵自顶向下展开的二叉树结构，每次递归都把当前序列分成两个规模更小的子序列。当序列被拆分到只剩一个元素时，便不再继续。因为单个元素可以视为天然有序，这也意味着递归来到了最底层。整个拆分过程的深度大约为 $logn$ ，随着递归的不断深入，原本完整的数据被切割为许多个最微小的 “基本单位” 。

![归并排序图像](src\content\posts\merge-sort\归并排序1.png)

### 有序合并阶段

当拆分不再继续时，算法开始反向回溯，此时每一步返回都伴随着 “合并” 操作的发生。两个分别已排序的子序列将被重新组合成一个更大的有序序列。合并时使用类似 “双指针” 的方式，从两个序列的开头开始比较大小，每次选择较小的元素加入结果中，然后将相应指针向前移动。随着比较逐渐推进，所有元素都会以从小到大的顺序重新归位。

![归并排序图像](src\content\posts\merge-sort\归并排序2.png)

在上图示例的最后一次合并中，两个长度为四的有序子序列 $[4,5,7,8]$ 和 $[1,2,3,6]$ 会依次比较并重组，最终得到全局排好序的结果 $[1,2,3,4,5,6,7,8]$ 。整个排序过程就是在这样的 “自底向上合并” 中逐渐完成的，局部的有序不断向外扩散，直到还原为完整序列。

这个优雅的过程展示了分治思想的精髓：将复杂问题拆分为简单问题，解决后再完美组合。无论数据初始状态如何混乱，归并排序都能以稳定且可靠的方式将其整理为正确的有序形式。

# 归并排序代码讲解

为了更清晰地理解算法的执行过程，我们将从整体框架出发，分析程序如何通过递归贯彻“分而治之”的思想，并在合并阶段将分散的小片段重新组合成一个有序数组。下面先来看代码的基本实现：

```cpp frame="code" title="main.cpp"
#include <bits/stdc++.h>
using namespace std;

void merge(int l, int r, int mid, int *a){
    int b[r - l + 1]; 
    int i = l, j = mid + 1, k = 0;

    while (i <= mid && j <= r){
        if (a[i] <= a[j]) b[k++] = a[i++];
        else b[k++] = a[j++];
    }
    while (i <= mid) b[k++] = a[i++];
    while (j <= r) b[k++] = a[j++];

    for (int i = 0; i < r - l + 1; i++){
        a[l + i] = b[i];
    }
}

void merge_sort(int l, int r, int *a){
    if (l == r) return;

    int mid = (l + r) / 2;
    merge_sort(l, mid, a);
    merge_sort(mid + 1, r, a);
    merge(l, r, mid, a);
}
```

## 递归结构解析

在学习归并排序时，许多人虽然能够写出代码，却没有真正理解递归为何能够逐层收敛。本节将从区间划分的角度出发，把这一过程的核心机制彻底讲清楚，使逻辑不再停留在记忆层面，而是能够真正掌握其中的含义。

递归函数的关键就在区间划分，而区间划分的关键就在计算中点 $mid$ 上。关于 $mid$ 的计算方式可以分为上取整和下取整两种方式，而上取整与下取整的差别，背后对应着两套完全不同的区间收敛路径。一看似简单的选择，决定了子区间能否持续缩小，也直接影响递归能否正确终止。接下来，我们就从 $mid$ 不同的计算方式入手，理解归并排序真正合理且稳定的划分方式。

### 情况一：下取整

我们直接考虑极限情况，当区间已经缩小到只有两个元素，即 $r = l + 1$ 时，根据公式可以得到：

$$
\displaystyle mid = \left\lfloor \frac{l + r}{2} \right\rfloor = \left\lfloor l + \frac{1}{2} \right\rfloor = l
$$

这意味着当左右端点相邻时 $mid$ 会与左端点重合。为了确保区间能够继续被有效划分，我们将区间切分为：

- 左区间 $[l, mid]$
- 右区间 $[mid + 1, r]$

这样无论如何，两个区间最终都能各自缩小到一个元素，符合归并排序的设计预期。因此在代码中常见这样的写法：

```cpp showLineNumbers
merge_sort(l, mid, a);
merge_sort(mid + 1, r, a);
```

如果我们尝试将区间划分成 $[l, mid]$ 和 $[mid, r]$ ，那么在 l 与 r 相邻时，得到的区间就会变为 $[l, l]$ 和 $[l, r]$ ，我们会发现右边的区间始终都是 $[l, r]$ 从而陷入死循环。

当区间已经缩小到只一个元素，即 $l == r$ 时，根据公式我们可以得到：

$$
\displaystyle mid = \left\lfloor \frac{l + r}{2} \right\rfloor = \left\lfloor l \right\rfloor = l
$$

如果按照之前的区间划分方式，我们会得到 $[l, l]$ 和 $[l + 1, l]$ 两个区间。左边的区间会进入无限循环状态，而右边的区间则直接进入非法状态。为了避免这种情况发生，我们需要在函数中明确阻止递归进入单元素区间，于是代码中加入了：

```cpp showLineNumbers
if (l == r) return;
```

这一判断确保递归在区间缩小到单个元素时能够正确终止，从而保证整个归并排序过程安全而稳定。

### 情况二：上取整

我们依旧考虑极限情况，当区间已经缩小到只有一个元素，即 $l = r$ 时，根据公式可以得到：

$$
\displaystyle mid = \left\lceil \frac{l + r}{2} \right\rceil = \left\lceil l + \frac{1}{2} \right\rceil = l + 1 = r
$$

这意味着当左右端点相邻时 $mid$ 会与右端点重合。为了确保区间能够继续被有效划分，我们将区间切分为：

- 左区间 $[l, mid - 1]$
- 右区间 $[mid, r]$

这样无论如何，两个区间最终都能各自缩小到一个元素，符合归并排序的设计预期。

跟上取整的情况类似，如果我们尝试将区间划分成 $[l, mid]$ 和 $[mid, r]$ ，那么在 l 与 r 相邻时，得到的区间就会变为 $[l, r]$ 和 $[r, r]$ ，我们会发现左边的区间始终都是 $[l, r]$ 从而陷入死循环。

当区间已经缩小到只一个元素，即 $l == r$ 时，根据公式我们可以得到：

$$
\displaystyle mid = \left\lceil \frac{l + r}{2} \right\rceil = \left\lceil r \right\rceil = r
$$

跟上取整的情况类似，我们会得到 $[r, r -  1]$ 和 $[r, r]$ 两个区间。右边的区间会进入无限循环状态，而左边的区间则直接进入非法状态，因此我们同样要禁止代码进入 $l == r$ 的状态。

## 合并结构解析

归并排序的核心不仅在于递归拆分区间，更在于如何将拆开的子区间重新合并为有序数组。理解这一点有助于我们掌握归并排序的 “分而治之” 思想的完整闭环。

在每一次递归返回时，两个子区间已经各自排好序，但整体仍然是分散的。合并函数的任务，就是通过比较两个子区间的元素，将它们按大小顺序依次放入一个临时数组中。具体来说，我们从两个子区间的起点开始，依次比较当前元素的大小，将较小的元素放入临时数组，并向前推进对应的指针。这个过程一直持续到其中一个子区间被完全取出为止。随后，将另一个子区间剩余的所有元素直接追加到临时数组末尾。最后，将临时数组的内容复制回原数组对应的位置，完成一次完整的归并。

这种合并策略保证了两个已排序的子区间能够高效、稳定地组合成更大的有序区间。值得注意的是，临时数组的大小总是等于待合并区间的长度，而每次合并的时间复杂度为 $O(n)$，其中 $n$ 为当前区间的长度。由于归并排序的递归深度为 $logn$，整体的时间复杂度为 $O(nlogn)$，这也是归并排序能够保持高效的原因之一。

通过理解递归的拆分逻辑和合并机制，我们就能清楚地看到归并排序的整体流程：每次递归都在缩小问题规模，而每次合并则在逐步恢复全局顺序。正是这种 “分而治之” 的思想，使得归并排序既稳定又高效，并且能够处理任意长度的数组而无需依赖额外的复杂操作。

# 双有序数组题目收集

既然归并排序在合并阶段的核心子问题是 **两个有序数组的合并** ，我们不妨思考一个更一般的情况：如果能够在合理时间复杂度内解决任意两个有序数组的问题，那么在处理单个无序数组时，我们同样可以借助归并排序的思路，在 $O(nlogn)$ 时间内完成该问题的求解。

实际上，这正体现了归并分治策略的精髓。许多涉及 **双有序数组** 的问题，本质上都是在不同条件下对两个已排好序的序列进行高效操作，无论是求交集、计算和、查找特定元素，还是统计某种关系。只要掌握了如何高效处理两个有序数组，就能够将复杂的单个无序数组问题拆解为更小的双有序数组子问题，并通过归并分治的思想将结果组合起来。因此，任何能够在合理时间内解决的双有序数组问题，都可以自然拓展到单个无序数组甚至更大规模的场景中。

接下来，就让我们看看不同的双有序数组题目，一起探讨它们是否能够被这种思路自然扩展，以及如何在归并分治框架下进行处理。

## 跨数组元素计数

[题目链接](https://www.geeksforgeeks.org/dsa/element-1st-array-count-elements-less-equal-2nd-array/)

### Problem Statement

给定两个未排序的数组 $A$ 和 $B$ ，两个数组都可能包含重复元素。对于 $A$ 数组的每个元素，求出 $B$ 数组中小于或等于该元素的元素数量。

### Constraints

- $1 ≤ n, m ≤ 2 × 10^5$
- $-10^9 ≤ A[i], B[i] ≤ 10^9$
- 所有输入都是整数

### Input

输入包含三行：

- 第一行包含连个整数 $n$ 和 $m$ ，分别表示数组 $A$ 和 $B$ 的长度
- 第二行包含 $n$ 个整数，表示数组 $A$ 中的元素
- 第三行包含 $m$ 个整数，表示数组 $B$ 中的元素

> $n \quad m$
> 
> $A_1 \quad A_2 \quad \ldots \quad A_n$
> 
> $B_1 \quad B_2 \quad \ldots \quad B_m$

### Output

输出长度为 $n$ 的数组作为答案。

### Sample Input 1

```txt showLineNumbers=false
6 6
1 2 3 4 7 9
0 1 2 1 1 4
```

### Sample Output 1

```txt showLineNumbers=false
4 5 5 6 6 6
```

### Sample Input 2

```txt showLineNumbers=false
5 7
4 8 7 5 1
4 48 3 0 1 1 5
```

### Sample Output 2

```txt showLineNumbers=false
5 6 6 6 3
```

## 计算数组的小和

[题目链接](https://www.nowcoder.com/practice/edfe05a1d45c4ea89101d936cac32469)

### Problem Statement

数组小和的定义：$\displaystyle \sum_{i=1}^{n}f_i$ ，其中 $f_i$ 的定义是第 $i$ 个数左侧小于等于 $s_i$ 的个数。

例如，数组 $s = [1, 3, 5, 2, 4, 6]$

- 在 $s[0]$ 的左边小于或等于 $s[0]$ 的数的和为 $0$

- 在 $s[1]$ 的左边小于或等于 $s[1]$ 的数的和为 $1$

- 在 $s[2]$ 的左边小于或等于 $s[2]$ 的数的和为 $1 + 3 = 4$

- 在 $s[3]$ 的左边小于或等于 $s[3]$ 的数的和为 $1$

- 在 $s[4]$ 的左边小于或等于 $s[4]$ 的数的和为 $1 + 3 + 2 = 6$

- 在 $s[5]$ 的左边小于或等于 $s[5]$ 的数的和为 $1 + 3 + 5 + 2 + 4 = 15$

所以 $s$ 的小和为 $0 + 1 + 4 + 1 + 6 + 15 = 27$

给定一个数组 $s$  ，实现函数返回 $s$ 的小和。

- $0 < n \leq 10^5$
- $-100 \leq s[i] \leq 100$

### Input

- 第一行包含一个整数 $N$ ，表示数组的长度
- 第二行包含 $N$ 个整数，表示数组中的各个元素

> $N$
> 
> $s_1 \quad s_2 \quad \ldots \quad s_N$

### Output

输出一个整数表示答案。

### Sample Input 1


# 深层问题思考

1. 排序算法理论上能做到比 $O(nlogn)$ 还要快吗？

    ### 比较排序的下界

    对于基于 **比较的排序** （如快速排序、归并排序、堆排序等），有一个著名结论：

    > 在最坏情况下，任意比较排序算法至少需要 $O(nlogn)$ 次比较。

    原因是对 $n$ 个元素的排列有 $n!$ 种可能，每一次比较最多只能把可能性缩小一半（类似二分决策树）。决策树的高度就是比较次数的下界，而高度满足：

    $$
    h \geq \log_2(n!) = O(nlogn)
    $$

    ### 非比较排序

    如果不依赖元素之间的比较，而是利用元素的其他特性（例如整数范围有限），就有可能突破 $O(nlogn)$ 的下界：

    - **计数排序（Counting Sort）**

        时间复杂度： $O(n + k)$ ，其中 $k$ 是元素的取值范围
        条件：元素必须是整数，且数据范围不能过大

    - **基数排序（Radix Sort）**

        时间复杂度： $O(nd)$ ，其中 $d$ 是数字的位数
        条件：元素为整数或可分解为位/字符的对象（如字符串）

    - **桶排序（Bucket Sort）**

        平均时间复杂度： $O(n + k)$ ，其中 $k$ 是桶的数量
        条件：元素在数值范围内均匀分布时效果最佳

    所以，如果元素类型允许非比较操作，排序速度可以达到线性时间 $O(n)$ 级别，理论上比 $O(nlogn)$ 更快。
